# 機能・非機能要件

[プロダクト戦略](1.プロダクト戦略.md)に基づき，作業の開始・継続から報酬時間の獲得・利用までに必要な要件を整理する．構成と通信経路は[プロダクト全体像](../spec/5.プロダクト全体像.md)を参照する．

- **機能要件**：利用者やシステムが「何をできるか」．例：作業を計測し，報酬時間を獲得・消費できる．
- **非機能要件**：機能を「どのような品質・条件で提供するか」．例：再送しても報酬が二重付与されず，取得データを適切に保護する．
- **優先度**：必須は初期版の受け入れ対象，推奨は基本ループの成立後に対応，発展は追加検証を伴う拡張とする．追加要件の「未定」は導入優先度が未確定であることを示し，要求する動作自体は以下に記載する．既存要件の優先度は維持し，拡張部分の初期版への採用は別途決定する．以下は要件であり，実装済みを意味しない．

## 今回確定した基本ループ

作業中に定期送信した記録から途中報酬を確定し，一時停止中の小休憩に使う．通常終了・中止時は未使用残高と残り利用枠をすべて破棄してスマホの制限を解除し，終了時の追加付与・次セッションへの持ち越しは行わない．途中付与条件・計算式は未定．

未終了セッションは本人につき1件，有効な制限対象iPhoneは1台．開始・再開はオンライン必須とし，iPhoneの適用確認を待たず開始できるが未確認を表示する．通信断中の記録・終了は端末に保存し，終了・中止の同期後に制限解除を進める．以下の「未定」は導入優先度を示し，この動作の合意とは区別する．

## 機能要件

| ---- | -------------- | ------------------------------------------------------------ | ------ |

| M-02 | タスク設定     | 作業名・作業予定時間・作業種類・本人が決める最小作業時間を設定                         | 必須   |
| M-03 | 集中タイマー   | 開始・一時停止・再開・本人による終了・中止（条件はM-15）                                         | 必須   |

| M-05 | アイドル検出   | 入力がない時間を検出し，放置判定の材料にする（読む作業との区別は要検証）                           | 必須   |
| M-06 | 集中度推定     | スクロール・タイピング・アイドルなどから集中度を推定（目の動きの利用可否は未定） | 必須   |

### バックエンド・端末連携

デスクトップアプリとiPhoneアプリはAPIを経由して連携する．報酬残高の正本はサーバー側で管理し，クライアントが任意の残高を直接DBに書き込む構成にしない．

| ID | 機能 | 要件 | 優先度 |
| --- | --- | --- | --- |
| B-01 | アカウント連携 | 同じ利用者の端末から作業履歴・報酬残高を参照でき，他の利用者のデータへアクセスできない | 必須 |
| B-02 | 作業記録の保存・集計 | 作業セッションと計測結果を保存し，作業・脱線・保留の時間を集計する | 必須 |
| B-03 | 報酬の確定 | 定期記録の未付与範囲から途中報酬を確定し，獲得履歴と残高を保存する．終了・中止時は追加付与せず未使用報酬を破棄する．付与条件・計算式は未定 | 必須 |
| B-04 | 報酬の消費 | 一時停止と直前記録の評価済みを確認し，残高内の利用枠を確保して履歴・残高を更新する．作業中・終了後・残高不足の利用要求は拒否する | 必須 |
| B-05 | 状態の同期 | 残高と報酬の獲得・消費結果を両アプリから取得できる | 必須 |
| B-06 | 通知 | 報酬獲得などをAPNs経由でiPhoneへ通知する．作業中の抑制はB-08，グループ通知はG-02に従う | 推奨 |

### 追加する開始・終了・利用制限・グループ要件

以下の動作は確定した要求とし，導入優先度は未定とする．

| ID | 機能 | 要件 | 優先度 |
| --- | --- | --- | --- |
| M-15 | 本人による終了・中止 | 最小時間をタスクごとに本人が開始前に設定し，開始時点の値を保持する．一時停止を除く計測時間が設定値以上なら本人が通常終了できる．自動終了はせず，未達でも中止し履歴を残せる．終了・中止とも未使用報酬をすべて破棄し，使用済み分は取り消さない | 未定 |
| M-16 | 起動時の開始導線 | アプリ起動時に開始ポップアップを表示する．未終了セッションがあればその画面へ案内し，重複作成しない．PCログイン・復帰・ロック解除のみを契機とする表示は対象外 | 未定 |
| I-12 | 制限モード・常時許可 | 登録アプリ指定／スマホ全体を選べ，両方で常時許可アプリを除く対象の実利用時間を合計して消費する．iPhone標準アプリは常時許可とするがSafariはその対象外．Safariは指定モードでは選択時，全体モードでは制限する | 未定 |
| B-07 | 作業再開時の利用枠終了 | 新規開始時は残高0で制限を要求する．再開時は未終了利用枠を失効させ，再制限する．枠の残りは返還せず破棄し，未充当残高は保持する．残高を追加減算しない | 未定 |
| B-08 | 作業中の報酬通知抑制 | 作業中・一時停止中は報酬獲得・解除開始などスマホ利用を促す通知を破棄し，終了後も再通知しない．状態同期と結果表示は継続する | 未定 |
| G-01 | 招待制グループ | グループの作成・招待・参加・退出を行える．公開検索・自由参加は対象外 | 未定 |
| G-02 | メンバーの作業開始通知 | 作業開始を開始者以外の現在の参加者のPCとiPhoneに通知する．受信者の作業中も通知し，PCではタスク開始画面へ案内する．再開は新規開始通知にせず，同じ開始イベントを重複通知しない | 未定 |

## 非機能要件

以下を初期版の品質要件案とする．数値目標が必要な項目は実機検証後に決定し，未測定の品質を保証済みと表現しない．

| ID | 分類 | 要件 | 確認方法 |
| --- | --- | --- | --- |
| N-01 | データ整合性 | 同一セッション・同一利用要求の再送や並行処理で，報酬の二重付与・二重消費・負の残高が発生しない | 同一要求の再送と並行要求を試し，履歴・残高の整合を確認 |
| N-02 | 通信障害への対応 | 同期失敗と処理中を表示し，未確定の報酬を確定済みとして表示しない．復旧後に結果を再確認できる | 送信前後の通信切断と復旧を試す |
| N-03 | 利用時間の整合性 | 実利用時間・残り利用枠・消費結果が矛盾しない．サーバーでの失効と端末での再制限完了を区別し，時間消費完了時の再制限をPush通知だけに依存させない | アプリの再起動・バックグラウンド移行・通知未受信を含めて実機確認 |
| N-04 | 認証・認可 | 作業履歴・報酬操作を本人に限定し，未認証・他利用者の要求を拒否する | 未認証と別アカウントによる参照・更新を検証 |
| N-05 | プライバシー | 計測対象と目的を説明し，必要な許可を得る．入力内容・画面画像などの取得範囲，保存先，保存期間を実装前に明確にする | 権限画面，送信データ，保存データ，ログを確認 |
| N-06 | 通信・秘密情報 | アプリとAPI間の通信をHTTPSとし，認証情報や接続用の秘密をソースコード・ログに残さない | 通信設定と秘密情報の管理・ログ出力を確認 |
| N-07 | 性能・資源消費 | 作業計測が通常の執筆・プログラミングを妨げない．CPU・メモリ・電池消費とAPI応答時間を測定する | 対象端末で作業中の負荷と応答時間を計測．合格数値は別途決定 |
| N-08 | 説明可能性・操作性 | 判定根拠，保留，残高，同期状況を理解できるように表示し，権限拒否時は使えない機能と必要な操作を案内する | 初回設定から報酬利用までの操作確認と利用者へのヒアリング |
| N-09 | 互換性 | 対応OS・バージョンと必要な権限を明示し，対応範囲で計測・制限・再制限を実機検証する | macOS・Windowsそれぞれの計測・権限と，iOSの制限・再制限の確認表を作成 |
| N-10 | 保守・運用 | API契約，DB変更，環境設定を管理し，失敗した同期・報酬処理を個人の作業内容を露出せず追跡できる | 契約・マイグレーションの検証とエラー時のログ確認 |

## 初期版の受け入れシナリオ

1. 同じアカウントで両アプリにログインし，デスクトップアプリで作業内容と予定時間を設定してセッションを開始できる．
2. 作業記録の定期送信で，合意したルールに基づく途中報酬が確定する．同じ記録範囲への二重付与はない（付与条件・計算式の確定後に検証）．
3. PCで一時停止し，直前までの記録送信と報酬評価後に，iPhoneで残高内の時間を選んで対象アプリを一時解除できる．実利用時間の消費完了・作業再開で再制限する．
4. 通常終了・中止では追加付与せず全未使用報酬を破棄して制限解除を要求する．終了結果と獲得・利用・破棄履歴を確認できる．
5. 通信失敗・再送・権限拒否時にも，残高の不整合や成功したように見える誤表示が発生しない．オフライン終了は同期後に解除を進め，端末適用未確認を表示する．

### 追加要件の受け入れシナリオ（導入時に適用）

1. 最小時間の直前では通常終了を拒否し，到達後は本人の操作で終了できる．一時停止時間は算入せず，予定時間や最小時間への到達だけでは終了しない．開始後の設定変更は進行中のセッションに反映しない．
2. 最小時間未満でも中止できる．終了・中止時は追加付与せず未使用残高と残り利用枠をすべて破棄して制限を解除する．使用済み報酬は取り消さず，競合・再送でも二重処理しない．
3. 未使用残高20分，解除枠10分のうち3分利用した状態で作業を再開すると，残り7分を破棄して再制限し，残高20分は保持する．再送でも返還・追加減算はない．
4. 両制限モードで対象アプリの実利用時間だけを消費し，未使用中・常時許可アプリの使用中は減らない．Safariは指定モードの選択有無と全体モードでの対象化を確認する．
5. 作業中・一時停止中の報酬通知は表示・再通知されず，グループの開始通知はPCとiPhoneで受け取れる．既送信通知の遅延到着・通信断を含む達成範囲はPoCで確認する．
6. 招待から参加・退出でき，非参加者・退出済み利用者・開始者本人には開始通知を送らない．再送や複数グループの重複関係でも端末ごとに重複通知しない．
7. アプリ起動時に開始導線を表示し，未終了セッションがあればその画面に案内する．
8. 許可失効と端末の再制限が同期できない場合は，未確認状態を表示する．失効後の遅延した解除適用報告で許可を復活させない．

## 実装前に決めること

- **対象環境**：macOS・Windowsの対応バージョン・CPUアーキテクチャ，Wails v2の画面用フレームワークとOS別の計測方式，iOSの対応バージョンと利用制限に必要な権限・配布条件．
- **判定と報酬**：読む作業と放置の区別，保留の扱い，集中スコアの計算，途中付与の条件・タイミング・対象範囲，報酬換算率・上限，目の動きの利用可否．
- **時間と同期**：実利用時間の計測精度・同期方法，計測送信間隔・上限，端末変更・故障時の引き継ぎ，解除失敗時の消費・返還，長時間通信断の復旧．開始・再開はオンライン必須，利用枠確保は一時停止中のみとする．
- **追加要件の詳細**：最小作業時間の初期値・入力範囲・予定時間との関係，常時許可する標準アプリの具体的一覧，グループの招待方式・管理権限・共有情報，PC通知配信方式，送信済み通知の遅延到着時の抑制，追加要件の導入優先度．
- **データと品質**：取得・送信する情報，保存期間・削除方法，性能の数値目標，運用費用の予算．
