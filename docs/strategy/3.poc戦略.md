# PoC戦略

## 目的と状態

[機能・非機能要件](2.機能-非機能要件.md)の追加要件について，OSで実現できる範囲・制約・必要な権限を確認する．以下は検証計画であり，実機検証は未実施．要求する動作を，動作確認済みの仕様として扱わない．

## 検証項目

| 対象 | 検証するシナリオ | 記録する結果 |
| --- | --- | --- |
| iOSの制限モード | 登録アプリ指定とスマホ全体で制限・解除する | Family Controlsの認可，配布条件，制御可能なアプリ・範囲，OS差 |
| 標準アプリの常時許可 | 標準アプリを利用可能にし，Safariだけは常時許可から除く | 標準アプリの具体的一覧，選択・除外可能な対象，Safariの制限可否．端末全体のロックとは区別 |
| 実利用時間 | 両モードで複数の対象アプリを使い，未使用中・常時許可アプリ使用中は消費しない | アプリ切替時の合計，アプリとWeb利用の重複計上の有無，閾値通知の精度・遅延，残り時間の表示方法 |
| 計測開始と継続 | 解除前の利用を含めず，解除後から計測する．アプリ終了・端末再起動・日付変更も試す | 計測継続・再登録の条件，消費履歴の保持，過去利用の混入の有無 |
| 作業開始・再開 | 利用枠10分のうち3分消費後に作業開始・再開する | 残り7分の失効と再制限，未使用残高の保持，適用確認までの遅延 |
| 再制限と通信断 | PC／iPhoneの通信切断，バックグラウンド，Push未受信，解除適用と失効の競合を試す | 即時再制限の達成範囲，端末状態未確認の表示，復旧時の順序照合，オフライン開始の許容条件 |
| PCの本人終了 | macOS・Windowsで最小時間の直前・到達時，一時停止，中止を試す | 自動終了しないこと，一時停止を除く時間，中止時の履歴と報酬なし，終了・中止の競合 |
| 起動時の導線 | 未終了セッションの有無を変えてアプリを起動する | 開始ポップアップと既存セッションへの案内．OSログイン・復帰だけでの表示は今回対象外 |
| 報酬通知の抑制 | 作業中・一時停止中に報酬獲得・解除開始を発生させ，送信前後で作業状態も切り替える | 未送信通知の破棄，再送なし，APNs受け付け済み通知の遅延到着を抑制できる範囲 |
| グループ通知 | 招待・参加・退出，新規開始と再開，複数グループ・複数端末を試す | 本人・非参加者への非配信，PCとiPhoneへの配信，作業中の受信，重複排除，PCからの開始導線 |

## 判断と記録

- OS・端末・権限・アプリ状態・通信状態・再現手順と，期待結果／実測結果を記録する．計測精度や遅延の合格数値は結果を踏まえて決める．
- AがiOSの制限・計測・通知，BがPCの計測，CがPCの導線・通知，Dが失効・同期・グループ・通知制御を担当する．通信断と競合は担当間で検証する．
- 要求を満たせない場合は制約と代替案を記録し，要件の変更を合意してから関連資料を更新する．実利用時間を黙って経過時間に置き換えない．

## 公式資料

- [DeviceActivityEvent](https://developer.apple.com/documentation/deviceactivity/deviceactivityevent)：アプリ・カテゴリ・Webドメインの利用時間と閾値イベント．
- [includesPastActivity](https://developer.apple.com/documentation/deviceactivity/deviceactivityevent/includespastactivity)：監視開始前の利用を含むかどうかの指定．
- [ShieldSettings](https://developer.apple.com/documentation/managedsettings/shieldsettings)：アプリ・Webサイトの制限設定．
- [ActivityCategoryPolicy.all(except:)](https://developer.apple.com/documentation/managedsettings/shieldsettings/activitycategorypolicy/all%28except%3A%29)：例外を指定したカテゴリ全体の制限．

これらのAPIの存在だけで，すべての標準アプリの例外設定や任意のタイミングでの再制限・通知抑制を保証しない．
