# ドメインモデル定義

## 1. 目的・設計方針

本書では，デスクトップでの作業計測，作業中の途中報酬確定，一時停止中の小休憩での利用，再開時の再制限，終了・中止時の未使用報酬破棄と制限解除を実現するモデルを定義する．報酬を次のセッションへ持ち越さない．

本書は設計案であり，実装済みを示すものではない．追加要件の導入優先度と未決事項は明示し，既存の暫定仕様と今回確定した仕様を区別する．

### 基本原則

1. 作業の計測結果と，サーバーで確定した作業結果を区別する．
2. 報酬の確定・残高・利用履歴はバックエンドを正本とする．
3. 報酬操作は冪等に実行し，同時操作でも残高を保護する．
4. iPhoneのアプリ制限操作は端末の責務とし，サーバーでは利用許可を管理する．
5. TASK / RELATED_TRANSITION / DISTRACTION / UNKNOWN / IDLEを区別し，判定器・適用ルール・保存スキーマのバージョンを分けて保持する．
6. 同期失敗・解除失敗・権限拒否を正常完了と区別する．

## 2. 境界づけられたコンテキスト

| コンテキスト                   | 責務                                                 |
| ------------------------------ | ---------------------------------------------------- |
| Identity                       | ユーザー識別，端末登録，データアクセス権限           |
| Focus                          | タスク設定，作業計測，行動分類，集中度評価，結果確定 |
| Reward                         | 報酬換算，報酬付与，残高管理，取引履歴               |
| Restriction                    | 制限対象・常時許可設定，実利用時間，利用許可，再制限の状態管理       |
| Group                         | 招待制グループ，所属，作業開始の共有                 |
| Synchronization / Notification | 再送管理，同期，通知イベントの処理                   |

各コンテキストは論理的に分割し，初期版では単一のGoアプリケーション内に実装する．具体的なモジュール構成・依存方向・トランザクション境界は[バックエンド構成](1.バックエンド構成.md)に従う．Synchronizationは各操作のapplicationと横断処理のworkflowが担う責務とし，Notificationは独立したnotificationモジュールとする．

## 3. Identityコンテキスト

### 3.1 User（ユーザー）

**種別：集約ルート**

同一アカウントをデスクトップとiPhoneで利用するための識別単位．

| 属性        | 型         | 説明                 |
| ----------- | ---------- | -------------------- |
| id          | UserID     | ユーザー識別子       |
| authProvider | String    | 認証基盤の識別子．採用構成ではsupabase |
| authSubject | String     | 検証済みSupabase JWTのsub（SupabaseユーザーID） |
| createdAt   | DateTime   | 登録日時             |
| status      | UserStatus | ACTIVE / DISABLED    |

**不変条件**

- `UserID`は変更されない．
- `authProvider`と`authSubject`の組み合わせで一意に対応づける．
- ユーザーの作業記録・報酬を操作する際は，認証済み主体との対応を検証する．

Supabase管理のauth.usersと業務Userは分離し，UserIDは独立した識別子とする案．受け入れるSupabaseプロジェクトは環境ごとに固定し，メールアドレスではなく検証済みsubjectで対応づける．初回登録のEnsureUser契約案と失効の扱いは[認証構成](6.認証構成.md)を参照する．認証用のセッションとWorkSessionは別物である．

### 3.2 Device（端末）

**種別：エンティティ**

| 属性         | 型           | 説明             |
| ------------ | ------------ | ---------------- |
| id           | DeviceID     | 端末識別子       |
| userId       | UserID       | 所有ユーザー     |
| platform     | Platform     | MACOS / WINDOWS / IOS      |
| deviceName   | String       | 表示用端末名     |
| lastSyncedAt | DateTime?    | 最終同期日時     |
| status       | DeviceStatus | ACTIVE / REVOKED |

初期版で有効な制限対象iPhoneは本人につき1台とする．端末変更・進行中セッションの計測端末の引き継ぎは未定．

APNsのデバイストークンは通知インフラ層で管理し，端末との関連を保持する．認証トークンや秘密情報をドメインエンティティへ直接含めない．

## 4. Focusコンテキスト

### 4.1 Task（タスク）

**種別：集約ルート**

ユーザーが行う作業の設定を表す．

| 属性            | 型           | 説明         |
| --------------- | ------------ | ------------ |
| id              | TaskID       | タスク識別子 |
| userId          | UserID       | 所有ユーザー |
| name            | String       | 作業名       |
| category        | TaskCategory | 作業種類     |
| mode            | FocusMode    | 無操作猶予を決める計測モード |
| plannedDuration | Duration     | 予定作業時間 |
| minimumDuration | Duration     | 本人が開始前に設定する最小作業時間 |
| createdAt       | DateTime     | 作成日時     |

**TaskCategoryの例**

- PROGRAMMING
- DOCUMENT_WRITING
- READING
- DESIGN
- STUDY
- OTHER

**FocusMode**

| モード | 無操作猶予 |
| ------ | ---------- |
| NORMAL | 60秒       |
| READING | 180秒     |
| VIDEO | 300秒       |

無操作時間が選択モードの猶予を超えた区間はUNKNOWNとする．猶予内の無操作だけではDISTRACTIONやIDLEと判定しない．IDLEは画面ロックまたはスリープが確定した区間に限る．

**TaskSnapshot**

セッション開始時に，タスク設定，FocusMode，適用対象のアプリ・domainルールを固定する．適用対象のルール値を参照IDだけでなく同じスナップショットへコピーし，rulesVersionも保存する．タスク設定やルールが後から変更されても既存セッションの判定を変えない．schemaVersionはスナップショットの保存形式を表し，rulesVersionとは別に管理する．

| 属性              | 型                         | 説明                                      |
| ----------------- | -------------------------- | ----------------------------------------- |
| mode              | FocusMode                  | セッション開始時の計測モード              |
| minimumDuration   | Duration                   | セッション開始時の最小作業時間            |
| appDomainRules    | List&lt;AppClassification&gt; | 適用するアプリ・domainルールの固定値      |
| rulesVersion      | String                     | 適用ルール一式のバージョン                |
| schemaVersion     | String                     | TaskSnapshot保存形式のバージョン          |

最小作業時間も`TaskSnapshot`に含め，開始後のタスク設定変更を進行中のセッションに反映しない．最小時間の初期値・入力範囲・予定時間との設定上の関係は未定．

### 4.2 WorkSession（作業セッション）

**種別：集約ルート**

作業の開始から終了・結果確定までを表す中心的なモデル．

| 属性           | 型                 | 説明                                      |
| -------------- | ------------------ | ----------------------------------------- |
| id             | SessionID          | セッション識別子                          |
| userId         | UserID             | 所有ユーザー                              |
| deviceId       | DeviceID           | 計測端末                                  |
| taskSnapshot   | TaskSnapshot       | 開始時点のタスク・FocusMode・適用ルール   |
| status         | SessionStatus      | セッション状態                            |
| startedAt      | DateTime           | 開始日時                                  |
| endedAt        | DateTime?          | 終了日時                                  |
| activeDuration | Duration           | 一時停止区間を除いた計測時間 E            |
| evaluation     | SessionEvaluation? | 確定した評価結果                          |
| version        | Integer            | 更新競合検知用バージョン                  |

**SessionStatus**

| 状態                | 意味                           |
| ------------------- | ------------------------------ |
| CREATED             | セッション作成済み             |
| RUNNING             | 計測中                         |
| PAUSED              | 一時停止中                     |
| COMPLETED_LOCAL     | デスクトップ側で終了し，送信待ち        |
| FINALIZING          | サーバーで結果確定中           |
| FINALIZED           | サーバーで結果確定済み         |
| FINALIZATION_FAILED | 確定処理に失敗し，再確認が必要 |
| ABORTED_LOCAL       | 端末で中止し，送信待ち         |
| ABORTED             | サーバーで中止を記録済み．未使用報酬は破棄，使用済み分は取消なし |

`COMPLETED_LOCAL`はデスクトップ側の状態であり，サーバー状態と混同しない．オフライン中はローカルで保持し，サーバーが終了結果を受信した後に`FINALIZING`へ移行する．

**操作**

- `start()`
- `pause()`
- `resume()`
- `finish()`：本人が通常終了する
- `abort()`：本人が中止し，未使用報酬を破棄する
- `finalize(evaluation)`

**不変条件**

- 未終了セッションは本人につき1件とし，一時停止中も新規開始を拒否する．
- 開始・再開はオンライン必須．サーバー受理後，iPhoneの制限適用確認を待たず計測できるが未確認を表示する．
- 終了・中止済みセッションを再開できない．
- `finish()`は`RUNNING`または`PAUSED`から，本人の操作かつ`activeDuration >= taskSnapshot.minimumDuration`の場合にのみ受け付ける．予定時間や最小時間への到達では自動終了しない．
- 最小時間の判定は一時停止を除く計測時間を用い，脱線・保留を除いた報酬計算対象時間とは区別する．
- `abort()`は`RUNNING`または`PAUSED`から受け付け，最小時間未満でも中止できる．履歴を残し，終了時の追加付与はしない．途中で使用済みの報酬は取り消さず，未使用分をすべて破棄する．
- `start()`と`resume()`は利用枠終了の契機となる．再開は同一セッションの一時停止からの復帰を指し，終了後は新規セッションを開始する．
- 一時停止中の時間はactiveDurationに加算しない．
- セッション全体の最終評価は通常終了時に一度だけ確定する．途中報酬用の区間評価・評価済み範囲は別に管理し，最終評価で再付与しない．
- 確定後の評価結果は通常操作では変更できない．
- 集計時間は計測区間から導出し，単純なクライアント申告値だけで確定しない．

**状態遷移と同期**

`CREATED → RUNNING ⇄ PAUSED`から，本人の通常終了で`COMPLETED_LOCAL → FINALIZING → FINALIZED`へ進む．確定失敗時は`FINALIZATION_FAILED`から同一操作で再試行する．本人の中止では`ABORTED_LOCAL → ABORTED`へ進む．通常終了・中止とも追加付与せず，全未使用残高と残り利用枠を破棄して制限解除を要求する．通常終了と中止の競合はバージョンと状態で検証し，二重に受理しない．開始・一時停止・再開・終了・中止もサーバーに同期し，通知判定と利用枠終了に用いる．通信断時の反映遅延は11.3節と11.4節の扱いに従う．

アプリ起動時に開始ポップアップを表示する．未終了のセッションがある場合はその画面へ案内し，新規セッションを重複作成しない．ログイン・スリープ復帰・ロック解除だけを契機とするポップアップは今回の対象外とする．

### 4.3 ActivitySegment（行動区間）

**種別：値オブジェクト**

作業セッション内の一定時間区間について，行動判定の結果を表す．

| 属性             | 型                         | 説明                           |
| ---------------- | -------------------------- | ------------------------------ |
| interval         | TimeInterval               | セッション内の計測区間         |
| classification   | ActivityClass              | 行動分類                       |
| confidence       | Float?                     | 校正済みの判定確信度。未算定はnull |
| reasons          | List&lt;EvidenceReason&gt; | 判定根拠                       |
| evaluatorVersion | String                     | 判定アルゴリズムのバージョン   |
| rulesVersion     | String                     | TaskSnapshotの適用ルール版     |

**ActivityClass**

- TASK（T）：タスク本体の作業区間
- RELATED_TRANSITION（R）：TaskSnapshotに固定した関連アプリ・domainルールに基づく関連区間
- DISTRACTION（D）：脱線先として登録されたアプリ・domainの区間
- UNKNOWN（U）：根拠不足，計測欠損，短い遷移などで分類を確定できない区間
- IDLE（I）：画面ロックまたはスリープが確定した区間

脱線先として登録されたアプリ・domainへ切り替えた後，その状態が連続10秒以上続いた場合は，切替開始時点まで遡ってDISTRACTIONとする．10秒未満で戻った短い遷移区間はUNKNOWNとする．

入力イベントからの経過時間だけではIDLEと判定しない．選択したFocusModeの無操作猶予を超えた区間はUNKNOWNとし，IDLEにするのは画面ロックまたはスリープが確定した場合に限る．confidenceは正答率ではなく，校正済みの値が得られない場合はnullとし，根拠のない数値を付けない．

### 4.4 ActivityEvidence（行動判定の根拠）

**種別：値オブジェクト**

| 属性             | 型              | 説明               |
| ---------------- | --------------- | ------------------ |
| kind             | EvidenceKind    | 根拠の種類         |
| value            | Number / String | 集計・分類された値 |
| observedInterval | TimeInterval    | 観測区間           |

**EvidenceKind**

- FOREGROUND_APP
- KEYBOARD_ACTIVITY
- MOUSE_ACTIVITY
- SCROLL_ACTIVITY
- IDLE_DURATION
- LOCK_STATE
- SLEEP_STATE
- APP_CLASSIFICATION
- WEBSITE_CLASSIFICATION（推奨）
- WORK_PROGRESS（発展）
- SCREEN_ANALYSIS（発展）

IDLE_DURATIONはFocusModeの無操作猶予を判定する根拠であり，それだけでIDLE分類にはしない．LOCK_STATEまたはSLEEP_STATEでロック・スリープを確定できた場合にIDLE分類へ使う．

原則として，キー入力内容や画面画像そのものではなく，分類結果や集計指標を保持する．

### 4.5 AppClassification（アプリ・domain分類設定）

**種別：エンティティ**

| 属性          | 型                  | 説明                                           |
| ------------- | ------------------- | ---------------------------------------------- |
| id            | AppClassificationID | 設定識別子                                     |
| userId        | UserID              | 所有ユーザー                                   |
| appIdentifier | String              | 必須の対象アプリ識別子                         |
| domain        | String?             | 任意の対象domain。完全一致で照合                |
| category      | AppCategory         | TASK / RELATED_TRANSITION / DISTRACTION          |
| updatedAt     | DateTime            | 更新日時                                       |

アプリIDは必須とし，domainを指定する場合はそのアプリ内の完全一致ホスト名として扱う．domain単独，wildcard，URL pathによる照合は行わない．適用ルールに一致しない区間はUNKNOWNとする．アプリ・domain分類は再利用可能なルールとして管理し，セッション開始時に対象タスクへ適用するルール値をTaskSnapshotへ固定する．以後のルール変更で過去の判定が変わらないようにする．

### 4.6 SessionEvaluation（セッション評価結果）

**種別：値オブジェクト**

| 属性                       | 型                          | 説明                                  |
| -------------------------- | --------------------------- | ------------------------------------- |
| taskDuration               | Duration                    | TASK時間 T                            |
| relatedTransitionDuration  | Duration                    | RELATED_TRANSITION時間 R              |
| workDuration               | Duration                    | 作業関連秒 T + R                      |
| distractionDuration        | Duration                    | DISTRACTION時間 D                     |
| unknownDuration            | Duration                    | UNKNOWN時間 U                         |
| idleDuration               | Duration                    | IDLE時間 I                            |
| focusScore                 | Float?                      | B100。0〜100，K=0ならnull             |
| Q                          | Float?                      | Q。0〜1，E=0ならnull                  |
| Wrate                      | Float?                      | Wrate。0〜1，E=0ならnull              |
| validWorkDuration          | Duration                    | 報酬計算対象時間                      |
| evaluatorVersion           | String                      | 判定アルゴリズムのバージョン          |
| rulesVersion               | String                      | TaskSnapshotに固定した適用ルール版    |
| schemaVersion              | String                      | SessionEvaluation保存形式のバージョン |
| segments                   | List&lt;ActivitySegment&gt; | 区間ごとの結果                        |

**計算**

T，R，D，U，Iはそれぞれ5種類のActivityClassの秒数を表す．Eは一時停止を除くactiveDuration，KはT + R + Dとする．

- E = T + R + D + U + I。PAUSED区間はEに含めない．
- workDuration = T + R
- K = T + R + D
- B100 = 100 × (T + R) / K。K=0の場合はnull
- Q = (T + R + D + I) / E。E=0の場合はnull
- Wrate = (T + R) / E。E=0の場合はnull

**不変条件**

- 各時間は0以上とする．
- 各時刻はTASK / RELATED_TRANSITION / DISTRACTION / UNKNOWN / IDLEのいずれか一つにだけ属し，区間は重複しない．
- workDuration = taskDuration + relatedTransitionDurationを満たす．
- E = T + R + D + U + Iを満たし，PAUSED区間は合計に含めない．
- focusScore（B100）は0〜100，QとWrateは0〜1の範囲とする．定義した分母が0の場合はnullとする．
- validWorkDurationはRewardPolicyで定義した条件に従って計算する．
- evaluatorVersionは判定アルゴリズム，rulesVersionは適用ルール，schemaVersionは保存形式を表し，互いに別の版として保持する．

途中付与の条件・計算式・保留時間の扱い・最小作業時間との関係は未定．最小作業時間は通常終了の条件として維持し，そのまま途中付与の条件とはしない．

### 4.7 PoCの実装状況と設計要件

現在のmacOS native collectorは，前面アプリ，入力アイドル秒数，Chrome / Safariのdomainを観測し，観測間から推定した前面区間とUNKNOWN区間を出力する．この分析だけでは作業関連性を判定しない．

追加されたevaluation packageは，明示したルールに基づく5分類と10秒継続時の遡及DISTRACTION，B100 / Q / Wrate，pauseを除外した評価時間を実装している．設定JSONを取得開始前に読み込み，`--session`付きのrecord / replayで同じルール・FocusModeを固定して評価する．設定と結果はevaluation.jsonへ保存される．pause区間は評価対象から除かれるが，UTC半開区間の指定によるオフラインreplayに限られる．record中の対話的pause/resumeや永続的なWorkSession管理はない．

IDLEは，評価器へ明示的な確定LOCK / SLEEP evidenceを与える人工データ経路でのみ計算できる．native collectorはLOCK / SLEEPを取得しないため，ライブ収集でIDLEを確定できない．ブラウザーのアプリルールはapp IDが必須で，Chrome / Safariではdomainも必須．domainは完全一致で照合し，wildcardとURL pathには対応しない．

現在の評価結果ではschema_versionとevaluator_versionをResult直下に置き，rules_versionはResult内のTaskSnapshotに保持する．TaskSnapshot固有のschemaVersionとActivitySegmentごとのevaluatorVersion / rulesVersionは本書が定める設計上の形であり，現行Resultでは個別に保持しない．confidenceは未校正のため設計値をnullとし，現行評価Resultはconfidence自体を出力しない．根拠のない数値は付けない．

このPoCはローカルの一回ごとの評価経路であり，サーバー上の結果確定・報酬処理・iPhone制限には接続していない．実装範囲と実機確認状態は[README](../../poc/macos-native/README.md)および[実機結果](../../poc/macos-native/docs/results.md)を参照する．

## 5. Rewardコンテキスト

### 5.1 RewardPolicy（報酬換算ルール）

**種別：ドメインポリシー**

| 属性              | 型             | 説明                               |
| ----------------- | -------------- | ---------------------------------- |
| id                | RewardPolicyID | ルール識別子                       |
| version           | Integer        | ルールバージョン                   |
| conversionRate    | Decimal        | 有効作業時間から報酬時間への換算率 |
| minimumFocusScore | Decimal        | 報酬対象となる最低集中度           |
| maximumReward     | Duration       | 付与上限                           |
| roundingRule      | RoundingRule   | 端数処理                           |
| effectiveFrom     | DateTime       | 適用開始日時                       |

報酬換算はドメインサービス`RewardCalculator`で実行する．

どの作業時間で付与するか，集中度条件，換算率，上限，端数処理は未定．上表はルールを表すモデル案であり，具体的な計算式を確定するものではない．

### 5.2 RewardWallet（報酬ウォレット）

**種別：集約ルート**

現在の作業セッションで使える未使用報酬時間を管理する．利用枠確保時に残高から差し引くため，解除中の残り時間はウォレット残高に含まない．再開時は未充当残高を保持し，通常終了・中止時は全額を破棄する．新規セッションに残高を持ち越さない．

| 属性           | 型       | 説明           |
| -------------- | -------- | -------------- |
| userId         | UserID   | 所有ユーザー   |
| sessionId      | SessionID? | 対象の未終了セッション．作業なしは未設定 |
| balanceSeconds | Integer  | 利用可能な秒数 |
| version        | Integer  | 更新競合検知   |
| updatedAt      | DateTime | 更新日時       |

**操作**

- `credit(reward)`
- `reserve(grant)`
- `release(reservation)`
- `getBalance()`
- `discardOnSessionEnd()`：未使用残高を0にし，破棄履歴を残す

**不変条件**

- `balanceSeconds >= 0`を常に満たす．
- 同じ報酬付与対象の記録範囲で二重に加算しない．バッチの分割・再送で報酬が増えないようにする．
- 終了・中止後の遅延記録・返還処理で残高を復活させない．
- 同じ利用要求で二重に差し引かない．
- 残高の更新と取引履歴の登録は同一トランザクションで確定する．

### 5.3 RewardTransaction（報酬取引）

**種別：エンティティ**

| 属性          | 型              | 説明           |
| ------------- | --------------- | -------------- |
| id            | TransactionID   | 取引識別子     |
| userId        | UserID          | 対象ユーザー   |
| type          | TransactionType | 取引種類       |
| amountSeconds | Integer         | 増減する秒数   |
| sourceId      | String          | 発生元の識別子 |
| sessionId     | SessionID       | 対象セッション |
| balanceAfter  | Integer         | 取引後残高     |
| occurredAt    | DateTime        | 確定日時       |

**TransactionType**

- EARN：報酬獲得
- SPEND：報酬利用枠の確保
- REFUND：解除失敗など，返還条件を満たした未利用枠の返還（再開・終了・中止による破棄は対象外）
- DISCARD：通常終了・中止による未使用ウォレット残高の破棄（利用枠の残り破棄はUsageGrantで記録し，二重減算しない）
- ADJUST：管理・補正（将来拡張）

取引履歴は原則として削除・上書きせず，誤処理の訂正は補正取引で表現する．

### 5.4 RewardGrant（報酬付与記録）

**種別：エンティティ**

| 属性          | 型            | 説明               |
| ------------- | ------------- | ------------------ |
| id            | RewardGrantID | 付与識別子         |
| sessionId     | SessionID     | 対象セッション     |
| userId        | UserID        | 対象ユーザー       |
| policyVersion | Integer       | 適用した報酬ルール |
| sourceRange   | RewardSourceRange | 付与対象の記録範囲を一意に識別する情報．具体的な型は未定 |
| earnedSeconds | Integer       | 獲得秒数           |
| transactionId | TransactionID | 対応する取引       |
| grantedAt     | DateTime      | 付与日時           |

1セッションに複数回の途中付与を許可するが，同じ記録範囲への二重付与は禁止する．SessionID単独の一意制約は設けない．受信バッチの重複排除とは別に，付与対象範囲を記録して重複を防ぐ．終了・中止時は追加付与せず，過去の付与・使用履歴は保持する．

## 6. Restrictionコンテキスト

### 6.1 RestrictionPolicy（利用制限設定）

**種別：集約ルート**

iPhoneで制限するアプリと制限方針を管理する．

| 属性      | 型                  | 説明                                     |
| --------- | ------------------- | ---------------------------------------- |
| id        | RestrictionPolicyID | 制限設定識別子                           |
| userId    | UserID              | 所有ユーザー                             |
| deviceId  | DeviceID            | 対象iPhone                               |
| status    | PolicyStatus        | ENABLED / DISABLED / PERMISSION_REQUIRED |
| targetMode | RestrictionTargetMode | SELECTED_APPS / DEVICE_WIDE             |
| usageTimeMode | UsageTimeMode    | ACTIVE_USAGE（実利用時間）               |
| allowedAppsPolicy | AllowedAppsPolicy | STANDARD_APPS_EXCEPT_SAFARI          |
| updatedAt | DateTime            | 更新日時                                 |

- `SELECTED_APPS`：あらかじめ登録したアプリのうち，常時許可アプリを除いた対象を制限し，対象全体の実利用時間を合計する．
- `DEVICE_WIDE`：スマホ全体のうち常時許可アプリを除いた対象を制限し，その実利用時間を合計する．端末そのもののロックを意味しない．
- 両モードとも，iPhone標準アプリは常時許可とし，その利用時間は報酬から消費しない．Safariは常時許可の対象外とし，アプリ指定モードでは選択された場合，全体モードでは制限対象とする．
- スマホを使用していない時間では報酬時間を消費しない．経過時間方式は採用しない．

標準アプリの具体的な対象一覧とOSでの制御可能範囲はPoCで確定する．選択アプリ・常時許可アプリのトークンなど，Appleフレームワーク固有の情報は端末側の安全な領域で管理する．

サーバーには，制限の設定状態や利用許可に必要なメタデータを保持する．

### 6.2 UsageGrant（利用許可）

**種別：集約ルート**

一時停止中に報酬時間を消費して，iPhoneの時間制限付き解除を要求した1回の操作を表す．作業終了・中止後の自由利用にはUsageGrantを発行しない．

| 属性             | 型               | 説明                 |
| ---------------- | ---------------- | -------------------- |
| id               | UsageGrantID     | 利用許可識別子       |
| userId           | UserID           | 利用ユーザー         |
| deviceId         | DeviceID         | 対象端末             |
| sessionId        | SessionID        | 利用枠が属する作業セッション |
| requestedSeconds | Integer          | 要求された利用秒数   |
| reservedSeconds  | Integer          | 確保された利用秒数   |
| status           | UsageGrantStatus | 利用許可状態         |
| issuedAt         | DateTime         | 発行日時             |
| activatedAt      | DateTime?        | 端末側解除の開始日時 |
| consumedSeconds  | Integer?         | 確認済み実利用秒数．未確認は未設定 |
| discardedSeconds | Integer?         | 再開・終了・中止等で破棄した秒数．未確認は未設定 |
| endReason        | UsageGrantEndReason? | USAGE_EXHAUSTED / WORK_STARTED / WORK_RESUMED / SESSION_FINISHED / SESSION_ABORTED |
| endedByOperationId | OperationID?    | 利用枠を終了した操作の識別子 |
| completedAt      | DateTime?        | 利用許可の終了確定日時（端末の適用完了とは別） |

**UsageGrantStatus**

- REQUESTED：利用要求を受信
- RESERVED：残高を確保し，利用許可発行済み
- ACTIVATED：端末が解除を適用したことを確認
- EXHAUSTED：実利用時間が利用枠に到達
- REVOKED：作業開始・再開・終了・中止によって利用枠が失効
- CANCELLED：利用許可の取消確定
- ACTIVATION_FAILED：端末側で解除に失敗

**不変条件**

- PAUSEDかつ停止直前までの記録受理・報酬評価が済んだ場合のみ，残高内の正の秒数を本人が指定して確保できる．
- 作業中・終了後・中止後・残高不足の利用要求は拒否する．
- 残高の確保と利用許可の発行は同一トランザクションで行う．
- 同一利用要求から複数の利用許可を発行しない．
- 初期版ではユーザーごとに同時に有効な利用許可を1件までとする．
- `EXHAUSTED`または`REVOKED`になった利用許可は，サーバーが有効な解除権限として扱わない．遅れて届いた解除適用報告で有効状態に戻さない．
- 確認済みの消費秒数は0以上かつ確保秒数以下とする．確定後は`reservedSeconds = consumedSeconds + discardedSeconds`を満たす（返還を伴う失敗・取消は別途精算）．
- `EXHAUSTED`では消費秒数を確保秒数，破棄秒数を0とする．`REVOKED`では終了までの実利用時間を確認して残りを破棄する．確認できない間は秒数を推測せず，利用許可の失効と精算未確認を区別する．
- 利用枠の失効では`REFUND`も追加の`SPEND`も作らない．残高は既に利用枠確保時に減算済みであり，残り時間だけを再利用不可にする．
- `ACTIVATED`はサーバーによる許可発行と区別し，端末からの適用確認を必要とする．

解除失敗時の返還条件は未定．端末の適用・利用状況を照合し，不明な場合は再同期対象とする．自動返還は確定しない．終了・中止後に返還報告が届いても残高を復活させない．

### 6.3 DeviceRestrictionState（端末の制限状態）

**種別：状態スナップショット**

| 属性             | 型               | 説明                 |
| ---------------- | ---------------- | -------------------- |
| deviceId         | DeviceID         | 対象iPhone           |
| permissionStatus | PermissionStatus | 権限状態             |
| shieldStatus     | ShieldStatus     | 制限状態             |
| activeGrantId    | UsageGrantID?    | 適用中の許可         |
| desiredMode      | RestrictionMode | 制限／時間付き解除／作業終了による解除 |
| controlRevision  | Integer         | サーバーが希望する制御の版 |
| appliedRevision  | Integer?        | 端末が適用を報告した版 |
| lastAppliedAt    | DateTime?        | 端末での最終適用日時 |
| lastReportedAt   | DateTime         | 最終報告日時         |

**ShieldStatus**

- SHIELDED：制限適用中
- UNSHIELDED：解除中
- UNKNOWN：状態未確認
- ERROR：制御エラー

この情報はiPhoneが報告した状態のスナップショットであり，サーバーから端末の現在状態を常に保証できるものではない．

端末側はセッション継続中の実利用時間の消費完了，または開始・再開による利用許可失効を確認して再制限を実行する．終了・中止時は制限解除を適用し，遅延した旧利用枠の消費完了で再制限しない．最新の制御リビジョンを優先する．サーバー上の失効だけで`SHIELDED`とみなさず，端末の適用報告を確認する．時間消費完了時の再制限は端末で管理し，Push通知の到着だけに依存しない．作業再開の即時反映と通信断時の扱いはPoCで検証する．

## 7. Synchronization / Notificationコンテキスト

同期操作は対象操作を所有するモジュールで管理する．横断操作の手順はworkflowが担い，起点モジュールが操作記録を所有する．通知イベント・Outboxと配信はnotificationが所有する．

### 7.1 SyncOperation（同期操作）

**種別：エンティティ**

| 属性            | 型              | 説明                         |
| --------------- | --------------- | ---------------------------- |
| id              | OperationID     | 冪等キー                     |
| userId          | UserID          | 実行ユーザー                 |
| operationType   | OperationType   | 操作種類                     |
| requestHash     | String          | リクエスト内容の識別値       |
| status          | OperationStatus | PENDING / SUCCEEDED / FAILED |
| resultReference | String?         | 確定結果の参照               |
| createdAt       | DateTime        | 作成日時                     |

同一ユーザー・操作種別・冪等キーの成功済み再送に対しては，元の処理結果を返す．記録不足など再試行可能な未完了操作は，前提が整った後に同じ内容・IDで再試行できる．

同じ冪等キーで異なる内容が送信された場合は，競合として拒否する．

計測データの分割アップロードについても，セッションIDと区間・バッチIDによる重複排除を行う．

### 7.2 NotificationEvent（通知イベント）

**種別：エンティティ**

| 属性        | 型                  | 説明                    |
| ----------- | ------------------- | ----------------------- |
| id          | NotificationEventID | 通知イベント識別子      |
| userId      | UserID              | 通知対象                |
| type        | NotificationType    | 通知種類                |
| referenceId | String              | 元イベント              |
| status      | NotificationStatus  | PENDING / SENT / FAILED / SUPPRESSED |
| deviceId    | DeviceID            | 通知先端末 |
| groupId     | GroupID?            | グループ通知の所属確認用 |
| createdAt   | DateTime            | 作成日時                |

通知種類の例：

- REWARD_EARNED：報酬獲得
- GRANT_ACTIVATED：利用開始
- GRANT_ENDED：実利用時間の消費完了または利用許可失効
- GROUP_WORK_STARTED：グループメンバーの作業開始

報酬付与の確定と通知イベントの登録を同一DBトランザクションで行う．グループ通知は作業開始イベントから生成し，元イベント・通知対象ユーザー・端末・通知種類で重複排除する．複数グループで同じ相手とつながっていても，同じ開始通知を同じ端末に重複表示しない．

`REWARD_EARNED`と`GRANT_ACTIVATED`は，通知対象ユーザーに`RUNNING`または`PAUSED`のセッションがある場合，`SUPPRESSED`として破棄する．通知生成時と送信・再試行直前に状態を検証し，抑制済みの通知は終了後も再送しない．報酬確定や状態同期そのものは止めず，画面で結果を確認できるようにする．

`GROUP_WORK_STARTED`は作業中も抑制しない．開始者本人を除く現在のグループ参加者のPCとiPhoneへ通知し，送信時にも参加状態を再確認する．受信者または開始者が退出して共有するグループがなくなった場合は送信しない．PCでは通知からタスク開始画面へ案内し，未終了セッションがあればその画面を表示する．通知内容・共有する作業情報の範囲は未定とする．

iPhoneへの送信はAPNs，PCへの配信方式は未定とする．`SENT`は配信基盤への送信受け付けを表し，到達・表示を保証しない．APNs受け付け後の遅延到着やiPhoneの通信断中の作業開始を含め，「作業中に表示しない」要求を実現できる範囲をPoCで検証する．

## 8. Groupコンテキスト

グループは招待制とし，公開検索や自由参加は対象外とする．具体的な招待手段や管理権限は未定．

| モデル | 種別 | 主な属性・責務 |
| --- | --- | --- |
| Group | 集約ルート | `id: GroupID`，`name: String`，`createdBy: UserID`，`createdAt: DateTime`．グループの識別と作成 |
| GroupMembership | エンティティ | `groupId: GroupID`，`userId: UserID`，`status: ACTIVE / LEFT`，`joinedAt: DateTime`，`leftAt: DateTime?`．参加・退出の管理 |
| GroupInvitation | エンティティ | `id: InvitationID`，`groupId: GroupID`，`invitedBy: UserID`，`status: PENDING / ACCEPTED / REVOKED / EXPIRED`，`acceptedBy: UserID?`．招待と受諾の管理 |

作成者は作成と同時に参加者となる．参加は有効な招待の受諾によって行い，退出は本人が行う．同じグループとユーザーの有効な所属は1件までとし，招待受諾の再送で所属を重複させない．招待発行・取消の権限，宛先・有効期限・利用回数，再参加，最後の参加者の退出時の扱いは実装前に確定する．

通知の共有は作業開始イベントに限定し，他人の作業記録・報酬残高・制限設定を操作する権限は付与しない．グループへの参加・退出によって個人の報酬残高を共有・変更しない．

## 9. 主要な業務規則と処理の調整

以下は論理的な責務の名称であり，すべてをdomain層のサービスとして実装するものではない．業務規則はdomain，単一モジュールの処理手順はapplication，複数モジュールの調整はworkflowに配置する．

| サービス・規則 | 配置・責務 |
| --- | --- |
| ActivityEvaluator | focus/domain：行動データからTASK / RELATED_TRANSITION / DISTRACTION / UNKNOWN / IDLEを判定 |
| FocusScoreCalculator | focus/domain：区間データからB100，Q，Wrateを計算 |
| RewardCalculator | reward/domain：確定結果とRewardPolicyから報酬秒数を計算 |
| InterimRewardService | workflow：focusの記録受理・評価範囲とrewardの途中付与・notificationのOutbox登録を調整 |
| SessionFinalizationService | workflow：focusの終了，rewardの残高破棄，restrictionの利用枠失効・制限解除要求を調整 |
| RewardWalletService | reward/application：domainの残高規則を適用し，付与・確保・返還と履歴保存を実行 |
| UsageGrantService | restriction/application：利用許可の発行・終了．rewardの残高確保との原子的な連携はworkflow |
| WorkSessionLifecycleService | focus/application：終了条件・中止・状態遷移をdomainで検証．開始・再開と利用枠失効の連携はworkflow |
| GroupService | group/application：domainの規則に従いグループ作成，招待・受諾，参加・退出を実行 |
| NotificationPolicy | notification/domain：渡された作業状態・所属情報から抑制と配信先を判定．情報取得・送信手順はapplication |
| RestrictionReconciliationService | restriction/application：domainの照合規則を使い，サーバー許可状態とiPhone報告状態の不一致を検出 |

計測値からの分類・集中度計算は，初期版ではデスクトップ側で実行してもよい．ただし，サーバーは結果を無条件に信頼せず，区間・合計・識別子・セッション状態を検証する．

## 11. 主要な処理と整合性

### 11.1 作業中の記録受理と途中報酬

1. PCが計測区間・分類・根拠をバッチIDと連番付きで定期送信する．
2. サーバーは本人・計測端末・セッション状態・区間の整合性を検証し，重複・不足範囲を確認する．
3. 未付与の記録範囲をポリシーで評価する．条件・計算式は未定であり，受信ごとに必ず報酬が発生するとは限らない．
4. workflowは1つのDBトランザクションで，記録・評価範囲，RewardGrant，RewardTransaction，RewardWallet，通知を導入する場合のOutbox／抑制状態，操作結果を確定する．
5. 受理状況・付与結果・残高を返す．バッチの再送と報酬対象範囲の重複を別々に防ぐ．

### 11.2 一時停止と小休憩

1. PCは計測を止め，停止直前までの記録を送る．停止要求には必要な最終バッチ連番を含める．
2. サーバーは記録が揃い評価済みであることを検証してPAUSEDへ変更する．不足中は利用枠を確保できない．
3. iPhoneは残高内で本人が指定した秒数を要求する．
4. サーバーはPAUSEDと有効利用枠なしを検証し，残高減算・取引履歴・利用許可・操作結果を同じトランザクションで確定する．
5. iPhoneは時間付き解除を適用し，適用結果と累積実利用時間を報告する．常時許可アプリの時間は消費に含めない．
6. 利用枠を使い切ったら，セッションが継続中の場合に端末で再制限する．

### 11.3 通信障害・再送

- 開始・再開はオンライン必須．サーバー受理後はiPhoneの制限適用を待たず計測できるが，適用未確認を表示する．
- 計測・一時停止・終了・中止の未送信記録はPCに保持する．一時停止中の報酬利用はサーバー確定後とする．
- 終了・中止がオフラインなら同期待ちとし，同期後にiPhoneの制限解除を要求する．端末の適用未確認と区別する．
- 応答喪失時は同じ操作IDで再送または結果照会する．別IDで報酬付与・利用枠確保をやり直さない．
- 端末状態が不明なら成功・失敗を推測して残高を修正しない．APNs失敗も報酬確定の取消理由にしない．

### 11.4 開始・再開と利用枠失効

開始時は未終了セッションがないことを確認し，作業状態と制限要求を確定する．再開時はPAUSEDを検証し，作業状態と未終了利用枠の失効を原子的に確定する．利用枠確保と競合制御し，同じ操作の再送で追加減算しない．新規開始のみグループ通知の生成対象とする．

未充当残高20分，利用枠10分のうち3分消費済みなら，再開で枠の残り7分を破棄し，残高20分を保持する．利用枠失効は端末の再制限完了とは別であり，未確認の消費・破棄秒数は推測しない．古い端末報告で失効済み許可を復活させない．

### 11.5 通常終了・中止

通常終了は計測記録と最小時間条件を検証する．中止は最小時間条件を課さない．終了操作の残り記録は報酬を発生させず履歴用に保存する．全未使用ウォレット残高をDISCARD取引で0にし，未終了利用枠を失効させ，セッション終了と制限解除要求・操作結果を同一トランザクションで確定する．使用済み報酬は取り消さない．

上の例で終了・中止した場合は，枠の残り7分に加えて残高20分も破棄する．利用枠の破棄はUsageGrant，未充当残高の破棄はRewardTransactionに記録し，二重減算しない．iPhoneは作業終了による解除を適用し，以後の自由利用を報酬時間として消費しない．

遅延記録は履歴保存と付与対象としての受理を区別し，終了後に残高を復活させない．終了と途中付与の競合では，先に付与が確定すれば終了処理で破棄し，終了が先なら付与しない．確定済み最終評価を遅延記録で黙って上書きしない．通信型と再送の詳細は[API仕様書](3.API仕様書.md)を参照する．
