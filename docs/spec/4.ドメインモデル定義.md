# ドメインモデル定義

## 1. 目的・設計方針

本書では，デスクトップでの作業計測から，集中度の評価，報酬時間の確定，iPhoneでの報酬利用・アプリ再制限までを実現するドメインモデルを定義する．

本書は設計案であり，実装済みを示すものではない．追加要件の導入優先度と未決事項は明示し，既存の暫定仕様と今回確定した仕様を区別する．

### 基本原則

1. 作業の計測結果と，サーバーで確定した作業結果を区別する．
2. 報酬の確定・残高・利用履歴はバックエンドを正本とする．
3. 報酬操作は冪等に実行し，同時操作でも残高を保護する．
4. iPhoneのアプリ制限操作は端末の責務とし，サーバーでは利用許可を管理する．
5. 作業・脱線・保留を区別し，判定根拠と推定方法のバージョンを保持する．
6. 同期失敗・解除失敗・権限拒否を正常完了と区別する．

## 2. 境界づけられたコンテキスト

| コンテキスト                   | 責務                                                 |
| ------------------------------ | ---------------------------------------------------- |
| Identity                       | ユーザー識別，端末登録，データアクセス権限           |
| Focus                          | タスク設定，作業計測，行動分類，集中度評価，結果確定 |
| Reward                         | 報酬換算，報酬付与，残高管理，取引履歴               |
| Restriction                    | 制限対象・常時許可設定，実利用時間，利用許可，再制限の状態管理       |
| Group                         | 招待制グループ，所属，作業開始の共有                 |
| Synchronization / Notification | 再送管理，同期，通知イベントの処理                   |

各コンテキストは論理的に分割し，初期版では単一のGoアプリケーション内に実装する．

## 3. Identityコンテキスト

### 3.1 User（ユーザー）

**種別：集約ルート**

同一アカウントをデスクトップとiPhoneで利用するための識別単位．

| 属性        | 型         | 説明                 |
| ----------- | ---------- | -------------------- |
| id          | UserID     | ユーザー識別子       |
| authProvider | String    | 外部認証プロバイダーの識別子 |
| authSubject | String     | プロバイダー内の主体識別子 |
| createdAt   | DateTime   | 登録日時             |
| status      | UserStatus | ACTIVE / DISABLED    |

**不変条件**

- `UserID`は変更されない．
- `authProvider`と`authSubject`の組み合わせで一意に対応づける．
- ユーザーの作業記録・報酬を操作する際は，認証済み主体との対応を検証する．

### 3.2 Device（端末）

**種別：エンティティ**

| 属性         | 型           | 説明             |
| ------------ | ------------ | ---------------- |
| id           | DeviceID     | 端末識別子       |
| userId       | UserID       | 所有ユーザー     |
| platform     | Platform     | MACOS / WINDOWS / IOS      |
| deviceName   | String       | 表示用端末名     |
| lastSyncedAt | DateTime?    | 最終同期日時     |
| status       | DeviceStatus | ACTIVE / REVOKED |

APNsのデバイストークンは通知インフラ層で管理し，端末との関連を保持する．認証トークンや秘密情報をドメインエンティティへ直接含めない．

## 4. Focusコンテキスト

### 4.1 Task（タスク）

**種別：集約ルート**

ユーザーが行う作業の設定を表す．

| 属性            | 型           | 説明         |
| --------------- | ------------ | ------------ |
| id              | TaskID       | タスク識別子 |
| userId          | UserID       | 所有ユーザー |
| name            | String       | 作業名       |
| category        | TaskCategory | 作業種類     |
| plannedDuration | Duration     | 予定作業時間 |
| minimumDuration | Duration     | 本人が開始前に設定する最小作業時間 |
| createdAt       | DateTime     | 作成日時     |

**TaskCategoryの例**

- PROGRAMMING
- DOCUMENT_WRITING
- READING
- DESIGN
- STUDY
- OTHER

タスク設定は再利用可能とする．過去の作業結果が変更されないように，セッション開始時にはタスクの設定内容をスナップショットとして保存する．

最小作業時間も`TaskSnapshot`に含め，開始後のタスク設定変更を進行中のセッションに反映しない．最小時間の初期値・入力範囲・予定時間との設定上の関係は未定．

### 4.2 WorkSession（作業セッション）

**種別：集約ルート**

作業の開始から終了・結果確定までを表す中心的なモデル．

| 属性           | 型                 | 説明                     |
| -------------- | ------------------ | ------------------------ |
| id             | SessionID          | セッション識別子         |
| userId         | UserID             | 所有ユーザー             |
| deviceId       | DeviceID           | 計測端末                 |
| taskSnapshot   | TaskSnapshot       | 開始時点のタスク情報     |
| status         | SessionStatus      | セッション状態           |
| startedAt      | DateTime           | 開始日時                 |
| endedAt        | DateTime?          | 終了日時                 |
| activeDuration | Duration           | 一時停止を除いた計測時間 |
| evaluation     | SessionEvaluation? | 確定した評価結果         |
| version        | Integer            | 更新競合検知用バージョン |

**SessionStatus**

| 状態                | 意味                           |
| ------------------- | ------------------------------ |
| CREATED             | セッション作成済み             |
| RUNNING             | 計測中                         |
| PAUSED              | 一時停止中                     |
| COMPLETED_LOCAL     | デスクトップ側で終了し，送信待ち        |
| FINALIZING          | サーバーで結果確定中           |
| FINALIZED           | サーバーで結果確定済み         |
| FINALIZATION_FAILED | 確定処理に失敗し，再確認が必要 |
| ABORTED_LOCAL       | 端末で中止し，送信待ち         |
| ABORTED             | サーバーで中止を記録済み．報酬なし |

`COMPLETED_LOCAL`はデスクトップ側の状態であり，サーバー状態と混同しない．オフライン中はローカルで保持し，サーバーが終了結果を受信した後に`FINALIZING`へ移行する．

**操作**

- `start()`
- `pause()`
- `resume()`
- `finish()`：本人が通常終了する
- `abort()`：本人が報酬なしで中止する
- `finalize(evaluation)`

**不変条件**

- 終了・中止済みセッションを再開できない．
- `finish()`は`RUNNING`または`PAUSED`から，本人の操作かつ`activeDuration >= taskSnapshot.minimumDuration`の場合にのみ受け付ける．予定時間や最小時間への到達では自動終了しない．
- 最小時間の判定は一時停止を除く計測時間を用い，脱線・保留を除いた報酬計算対象時間とは区別する．
- `abort()`は`RUNNING`または`PAUSED`から受け付け，最小時間未満でも中止できる．履歴を残し，報酬を付与しない．
- `start()`と`resume()`は利用枠終了の契機となる．再開は同一セッションの一時停止からの復帰を指し，終了後は新規セッションを開始する．
- 一時停止中は作業時間を加算しない．
- 同一セッションの評価結果は一度だけ確定する．
- 確定後の評価結果は通常操作では変更できない．
- 集計時間は計測区間から導出し，単純なクライアント申告値だけで確定しない．

**状態遷移と同期**

`CREATED → RUNNING ⇄ PAUSED`から，本人の通常終了で`COMPLETED_LOCAL → FINALIZING → FINALIZED`へ進む．確定失敗時は`FINALIZATION_FAILED`から同一操作で再試行する．本人の中止では`ABORTED_LOCAL → ABORTED`へ進み，報酬確定処理には進まない．通常終了と中止の競合はバージョンと状態で検証し，二重に受理しない．開始・一時停止・再開・終了・中止もサーバーに同期し，通知判定と利用枠終了に用いる．通信断時の反映遅延は11.3節と11.4節の扱いに従う．

アプリ起動時に開始ポップアップを表示する．未終了のセッションがある場合はその画面へ案内し，新規セッションを重複作成しない．ログイン・スリープ復帰・ロック解除だけを契機とするポップアップは今回の対象外とする．

### 4.3 ActivitySegment（行動区間）

**種別：値オブジェクト**

作業セッション内の一定時間区間について，行動判定の結果を表す．

| 属性             | 型                         | 説明                         |
| ---------------- | -------------------------- | ---------------------------- |
| interval         | TimeInterval               | セッション内の計測区間       |
| classification   | ActivityClass              | 行動分類                     |
| confidence       | Float                      | 推定の確信度                 |
| reasons          | List&lt;EvidenceReason&gt; | 判定根拠                     |
| evaluatorVersion | String                     | 判定アルゴリズムのバージョン |

**ActivityClass**

- WORK：作業
- DISTRACTION：脱線
- PENDING：判断保留

判定に十分な根拠がない場合は`PENDING`とする．

例えば，入力操作がないという理由だけで，読書中の時間を脱線と確定しない．

### 4.4 ActivityEvidence（行動判定の根拠）

**種別：値オブジェクト**

| 属性             | 型              | 説明               |
| ---------------- | --------------- | ------------------ |
| kind             | EvidenceKind    | 根拠の種類         |
| value            | Number / String | 集計・分類された値 |
| observedInterval | TimeInterval    | 観測区間           |

**EvidenceKind**

- FOREGROUND_APP
- KEYBOARD_ACTIVITY
- MOUSE_ACTIVITY
- SCROLL_ACTIVITY
- IDLE_DURATION
- APP_CLASSIFICATION
- WEBSITE_CLASSIFICATION（推奨）
- WORK_PROGRESS（発展）
- SCREEN_ANALYSIS（発展）

原則として，キー入力内容や画面画像そのものではなく，分類結果や集計指標を保持する．

### 4.5 AppClassification（アプリ分類設定）

**種別：エンティティ**

| 属性          | 型                  | 説明                           |
| ------------- | ------------------- | ------------------------------ |
| id            | AppClassificationID | 設定識別子                     |
| userId        | UserID              | 所有ユーザー                   |
| appIdentifier | String              | アプリの識別子                 |
| category      | AppCategory         | WORK / ENTERTAINMENT / UNKNOWN |
| updatedAt     | DateTime            | 更新日時                       |

アプリ分類は集中度推定の入力であり，それだけで作業・脱線を最終確定するものではない．

### 4.6 SessionEvaluation（セッション評価結果）

**種別：値オブジェクト**

| 属性                | 型                          | 説明                   |
| ------------------- | --------------------------- | ---------------------- |
| workDuration        | Duration                    | 作業時間               |
| distractionDuration | Duration                    | 脱線時間               |
| pendingDuration     | Duration                    | 保留時間               |
| focusScore          | Float                       | 集中スコア             |
| validWorkDuration   | Duration                    | 報酬計算対象時間       |
| evaluatorVersion    | String                      | 判定ルールのバージョン |
| segments            | List&lt;ActivitySegment&gt; | 区間ごとの結果         |

**不変条件**

- 各時間は0以上とする．
- 作業・脱線・保留の区間は重複しない．
- `workDuration + distractionDuration + pendingDuration = activeDuration`を満たす．
- `focusScore`は0〜1の範囲で管理する．
- `validWorkDuration`は報酬ポリシーで定義した条件に従って計算する．

初期版では保留時間を報酬対象外とする案を暫定採用する．この扱いは，ユーザーへの説明と実機検証を経て確定する．

## 5. Rewardコンテキスト

### 5.1 RewardPolicy（報酬換算ルール）

**種別：ドメインポリシー**

| 属性              | 型             | 説明                               |
| ----------------- | -------------- | ---------------------------------- |
| id                | RewardPolicyID | ルール識別子                       |
| version           | Integer        | ルールバージョン                   |
| conversionRate    | Decimal        | 有効作業時間から報酬時間への換算率 |
| minimumFocusScore | Decimal        | 報酬対象となる最低集中度           |
| maximumReward     | Duration       | 付与上限                           |
| roundingRule      | RoundingRule   | 端数処理                           |
| effectiveFrom     | DateTime       | 適用開始日時                       |

報酬換算はドメインサービス`RewardCalculator`で実行する．

暫定例：

`earnedSeconds = floor(validWorkSeconds × conversionRate)`

実際には集中スコア条件，上限，端数処理を適用する．

### 5.2 RewardWallet（報酬ウォレット）

**種別：集約ルート**

ユーザーが保有する未使用の報酬時間を管理する．利用枠確保時に残高から差し引くため，解除中の残り時間はウォレット残高に含まない．作業開始・再開時も未使用残高は保持する．

| 属性           | 型       | 説明           |
| -------------- | -------- | -------------- |
| userId         | UserID   | 所有ユーザー   |
| balanceSeconds | Integer  | 利用可能な秒数 |
| version        | Integer  | 更新競合検知   |
| updatedAt      | DateTime | 更新日時       |

**操作**

- `credit(reward)`
- `reserve(grant)`
- `release(reservation)`
- `getBalance()`

**不変条件**

- `balanceSeconds >= 0`を常に満たす．
- 同じ報酬付与原因で二重に加算しない．
- 同じ利用要求で二重に差し引かない．
- 残高の更新と取引履歴の登録は同一トランザクションで確定する．

### 5.3 RewardTransaction（報酬取引）

**種別：エンティティ**

| 属性          | 型              | 説明           |
| ------------- | --------------- | -------------- |
| id            | TransactionID   | 取引識別子     |
| userId        | UserID          | 対象ユーザー   |
| type          | TransactionType | 取引種類       |
| amountSeconds | Integer         | 増減する秒数   |
| sourceId      | String          | 発生元の識別子 |
| balanceAfter  | Integer         | 取引後残高     |
| occurredAt    | DateTime        | 確定日時       |

**TransactionType**

- EARN：報酬獲得
- SPEND：報酬利用枠の確保
- REFUND：解除失敗など，返還条件を満たした未利用枠の返還（作業開始・再開による残り時間の破棄は対象外）
- ADJUST：管理・補正（将来拡張）

取引履歴は原則として削除・上書きせず，誤処理の訂正は補正取引で表現する．

### 5.4 RewardGrant（報酬付与記録）

**種別：エンティティ**

| 属性          | 型            | 説明               |
| ------------- | ------------- | ------------------ |
| id            | RewardGrantID | 付与識別子         |
| sessionId     | SessionID     | 対象セッション     |
| userId        | UserID        | 対象ユーザー       |
| policyVersion | Integer       | 適用した報酬ルール |
| earnedSeconds | Integer       | 獲得秒数           |
| transactionId | TransactionID | 対応する取引       |
| grantedAt     | DateTime      | 付与日時           |

1つの通常終了・確定済みセッションに対する通常の報酬付与は1回に限定する．中止セッションには付与しない．

## 6. Restrictionコンテキスト

### 6.1 RestrictionPolicy（利用制限設定）

**種別：集約ルート**

iPhoneで制限するアプリと制限方針を管理する．

| 属性      | 型                  | 説明                                     |
| --------- | ------------------- | ---------------------------------------- |
| id        | RestrictionPolicyID | 制限設定識別子                           |
| userId    | UserID              | 所有ユーザー                             |
| deviceId  | DeviceID            | 対象iPhone                               |
| status    | PolicyStatus        | ENABLED / DISABLED / PERMISSION_REQUIRED |
| targetMode | RestrictionTargetMode | SELECTED_APPS / DEVICE_WIDE             |
| usageTimeMode | UsageTimeMode    | ACTIVE_USAGE（実利用時間）               |
| allowedAppsPolicy | AllowedAppsPolicy | STANDARD_APPS_EXCEPT_SAFARI          |
| updatedAt | DateTime            | 更新日時                                 |

- `SELECTED_APPS`：あらかじめ登録したアプリのうち，常時許可アプリを除いた対象を制限し，対象全体の実利用時間を合計する．
- `DEVICE_WIDE`：スマホ全体のうち常時許可アプリを除いた対象を制限し，その実利用時間を合計する．端末そのもののロックを意味しない．
- 両モードとも，iPhone標準アプリは常時許可とし，その利用時間は報酬から消費しない．Safariは常時許可の対象外とし，アプリ指定モードでは選択された場合，全体モードでは制限対象とする．
- スマホを使用していない時間では報酬時間を消費しない．経過時間方式は採用しない．

標準アプリの具体的な対象一覧とOSでの制御可能範囲はPoCで確定する．選択アプリ・常時許可アプリのトークンなど，Appleフレームワーク固有の情報は端末側の安全な領域で管理する．

サーバーには，制限の設定状態や利用許可に必要なメタデータを保持する．

### 6.2 UsageGrant（利用許可）

**種別：集約ルート**

報酬時間を消費して，iPhoneの制限解除を要求した1回の操作を表す．

| 属性             | 型               | 説明                 |
| ---------------- | ---------------- | -------------------- |
| id               | UsageGrantID     | 利用許可識別子       |
| userId           | UserID           | 利用ユーザー         |
| deviceId         | DeviceID         | 対象端末             |
| requestedSeconds | Integer          | 要求された利用秒数   |
| reservedSeconds  | Integer          | 確保された利用秒数   |
| status           | UsageGrantStatus | 利用許可状態         |
| issuedAt         | DateTime         | 発行日時             |
| activatedAt      | DateTime?        | 端末側解除の開始日時 |
| consumedSeconds  | Integer?         | 確認済み実利用秒数．未確認は未設定 |
| discardedSeconds | Integer?         | 作業開始・再開で破棄した秒数．未確認は未設定 |
| endReason        | UsageGrantEndReason? | USAGE_EXHAUSTED / WORK_STARTED / WORK_RESUMED |
| endedByOperationId | OperationID?    | 利用枠を終了した操作の識別子 |
| completedAt      | DateTime?        | 利用許可の終了確定日時（端末の適用完了とは別） |

**UsageGrantStatus**

- REQUESTED：利用要求を受信
- RESERVED：残高を確保し，利用許可発行済み
- ACTIVATED：端末が解除を適用したことを確認
- EXHAUSTED：実利用時間が利用枠に到達
- REVOKED：作業開始・再開によって利用枠が失効
- CANCELLED：利用許可の取消確定
- ACTIVATION_FAILED：端末側で解除に失敗

**不変条件**

- 残高不足の利用要求は拒否する．
- 残高の確保と利用許可の発行は同一トランザクションで行う．
- 同一利用要求から複数の利用許可を発行しない．
- 初期版ではユーザーごとに同時に有効な利用許可を1件までとする．
- `EXHAUSTED`または`REVOKED`になった利用許可は，サーバーが有効な解除権限として扱わない．遅れて届いた解除適用報告で有効状態に戻さない．
- 確認済みの消費秒数は0以上かつ確保秒数以下とする．確定後は`reservedSeconds = consumedSeconds + discardedSeconds`を満たす（返還を伴う失敗・取消は別途精算）．
- `EXHAUSTED`では消費秒数を確保秒数，破棄秒数を0とする．`REVOKED`では終了までの実利用時間を確認して残りを破棄する．確認できない間は秒数を推測せず，利用許可の失効と精算未確認を区別する．
- 作業開始・再開による失効では`REFUND`も追加の`SPEND`も作らない．残高は既に利用枠確保時に減算済みであり，残り時間だけを再利用不可にする．
- `ACTIVATED`はサーバーによる許可発行と区別し，端末からの適用確認を必要とする．

解除に失敗した場合でも，残高を即座に返還できるとは限らない．端末側のShield状態を確認し，利用ができなかったことを確認できる場合に返還する．不明な場合は調査・再同期対象とする．

### 6.3 DeviceRestrictionState（端末の制限状態）

**種別：状態スナップショット**

| 属性             | 型               | 説明                 |
| ---------------- | ---------------- | -------------------- |
| deviceId         | DeviceID         | 対象iPhone           |
| permissionStatus | PermissionStatus | 権限状態             |
| shieldStatus     | ShieldStatus     | 制限状態             |
| activeGrantId    | UsageGrantID?    | 適用中の許可         |
| lastAppliedAt    | DateTime?        | 端末での最終適用日時 |
| lastReportedAt   | DateTime         | 最終報告日時         |

**ShieldStatus**

- SHIELDED：制限適用中
- UNSHIELDED：解除中
- UNKNOWN：状態未確認
- ERROR：制御エラー

この情報はiPhoneが報告した状態のスナップショットであり，サーバーから端末の現在状態を常に保証できるものではない．

端末側は実利用時間の消費完了または利用許可の失効を確認して再制限を実行する．サーバー上の失効だけで`SHIELDED`とみなさず，端末の適用報告を確認する．時間消費完了時の再制限は端末で管理し，Push通知の到着だけに依存しない．作業再開の即時反映と通信断時の扱いはPoCで検証する．

## 7. Synchronization / Notificationコンテキスト

### 7.1 SyncOperation（同期操作）

**種別：エンティティ**

| 属性            | 型              | 説明                         |
| --------------- | --------------- | ---------------------------- |
| id              | OperationID     | 冪等キー                     |
| userId          | UserID          | 実行ユーザー                 |
| operationType   | OperationType   | 操作種類                     |
| requestHash     | String          | リクエスト内容の識別値       |
| status          | OperationStatus | PENDING / SUCCEEDED / FAILED |
| resultReference | String?         | 確定結果の参照               |
| createdAt       | DateTime        | 作成日時                     |

同一ユーザー・操作種別・冪等キーの再送に対しては，元の処理結果を返す．

同じ冪等キーで異なる内容が送信された場合は，競合として拒否する．

計測データの分割アップロードについても，セッションIDと区間・バッチIDによる重複排除を行う．

### 7.2 NotificationEvent（通知イベント）

**種別：エンティティ**

| 属性        | 型                  | 説明                    |
| ----------- | ------------------- | ----------------------- |
| id          | NotificationEventID | 通知イベント識別子      |
| userId      | UserID              | 通知対象                |
| type        | NotificationType    | 通知種類                |
| referenceId | String              | 元イベント              |
| status      | NotificationStatus  | PENDING / SENT / FAILED / SUPPRESSED |
| deviceId    | DeviceID            | 通知先端末 |
| groupId     | GroupID?            | グループ通知の所属確認用 |
| createdAt   | DateTime            | 作成日時                |

通知種類の例：

- REWARD_EARNED：報酬獲得
- GRANT_ACTIVATED：利用開始
- GRANT_ENDED：実利用時間の消費完了または利用許可失効
- GROUP_WORK_STARTED：グループメンバーの作業開始

報酬付与の確定と通知イベントの登録を同一DBトランザクションで行う．グループ通知は作業開始イベントから生成し，元イベント・通知対象ユーザー・端末・通知種類で重複排除する．複数グループで同じ相手とつながっていても，同じ開始通知を同じ端末に重複表示しない．

`REWARD_EARNED`と`GRANT_ACTIVATED`は，通知対象ユーザーに`RUNNING`または`PAUSED`のセッションがある場合，`SUPPRESSED`として破棄する．通知生成時と送信・再試行直前に状態を検証し，抑制済みの通知は終了後も再送しない．報酬確定や状態同期そのものは止めず，画面で結果を確認できるようにする．

`GROUP_WORK_STARTED`は作業中も抑制しない．開始者本人を除く現在のグループ参加者のPCとiPhoneへ通知し，送信時にも参加状態を再確認する．受信者または開始者が退出して共有するグループがなくなった場合は送信しない．PCでは通知からタスク開始画面へ案内し，未終了セッションがあればその画面を表示する．通知内容・共有する作業情報の範囲は未定とする．

iPhoneへの送信はAPNs，PCへの配信方式は未定とする．`SENT`は配信基盤への送信受け付けを表し，到達・表示を保証しない．APNs受け付け後の遅延到着やオフラインの作業開始を含め，「作業中に表示しない」要求を実現できる範囲をPoCで検証する．

## 8. Groupコンテキスト

グループは招待制とし，公開検索や自由参加は対象外とする．具体的な招待手段や管理権限は未定．

| モデル | 種別 | 主な属性・責務 |
| --- | --- | --- |
| Group | 集約ルート | `id: GroupID`，`name: String`，`createdBy: UserID`，`createdAt: DateTime`．グループの識別と作成 |
| GroupMembership | エンティティ | `groupId: GroupID`，`userId: UserID`，`status: ACTIVE / LEFT`，`joinedAt: DateTime`，`leftAt: DateTime?`．参加・退出の管理 |
| GroupInvitation | エンティティ | `id: InvitationID`，`groupId: GroupID`，`invitedBy: UserID`，`status: PENDING / ACCEPTED / REVOKED / EXPIRED`，`acceptedBy: UserID?`．招待と受諾の管理 |

作成者は作成と同時に参加者となる．参加は有効な招待の受諾によって行い，退出は本人が行う．同じグループとユーザーの有効な所属は1件までとし，招待受諾の再送で所属を重複させない．招待発行・取消の権限，宛先・有効期限・利用回数，再参加，最後の参加者の退出時の扱いは実装前に確定する．

通知の共有は作業開始イベントに限定し，他人の作業記録・報酬残高・制限設定を操作する権限は付与しない．グループへの参加・退出によって個人の報酬残高を共有・変更しない．

## 11. 主要な処理と整合性

### 11.1 集中セッションの確定と報酬付与

1. デスクトップ側で作業区間を計測する．
2. デスクトップ側で行動分類・集中スコアを推定する．
3. 終了結果を同一SessionID・冪等キーでサーバーへ送信する．
4. サーバーでセッション状態，計測区間，集計値，最小作業時間以上であること，本人による通常終了であることを検証する．
5. `SessionEvaluation`を確定する．
6. `RewardPolicy`に従って報酬を算出する．
7. 1つのDBトランザクションで`RewardGrant`，`RewardTransaction`，`RewardWallet`，通知Outboxを更新する．
8. 確定結果をデスクトップへ返す．

同時再送の場合も，同一SessionIDに対する付与の一意制約で二重付与を防止する．中止は履歴保存のみとし，報酬付与処理には進まない．通常終了の報酬通知も，送信時に別セッションで作業中なら抑制する．

### 11.2 報酬の利用

両制限モードとも，常時許可アプリを除いた制限対象の「実利用時間」で消費する．

1. iPhoneで利用したい秒数を選択する．
2. `UsageGrantService`に利用許可を要求する．
3. サーバーが残高と同時利用状態を検証する．
4. 1つのDBトランザクションで残高を確保し，取引履歴と利用許可を記録する．
5. iPhoneで解除許可を受信し，Shieldを解除する．
6. iPhoneが適用結果をサーバーへ報告する．
7. 端末側で解除適用後の対象アプリの実利用時間を計測し，確保した時間の消費完了後に再制限する．適用前の利用時間を含めない．
8. 次回同期で端末の制限状態と利用許可を照合する．

確保した時間を1回の解除枠に充当する．作業開始・再開時の残りは返還せず，未使用残高は保持する．解除失敗やその他の取消に対する返還条件は，実利用の確認方法とともに別途確定する．

### 11.3 通信障害

- デスクトップの未送信記録は端末内に保存する．
- 同一セッションの送信は同一識別子で再試行する．
- API応答が失われた場合は，新しい報酬を付与するのではなく既存結果を照会する．
- iPhoneが解除許可を受信できなかった場合も，操作IDで確定状態を照会する．
- iPhoneの解除状態が不明な場合，成功・失敗を推測して残高を修正しない．
- APNs通知の失敗は報酬確定の取消理由としない．

### 11.4 作業開始・再開と利用枠の失効

1. 本人の開始・再開要求をセッションと操作IDに対応づけて受け付ける．
2. サーバーでは利用許可の発行と開始・再開処理をユーザー単位で直列化し，その時点の未終了の利用枠（`RESERVED`／`ACTIVATED`）を`REVOKED`にする．原因を`WORK_STARTED`／`WORK_RESUMED`として記録し，作業状態と失効の更新を原子的に確定する．
3. iPhoneへ許可終了を同期し，再制限を要求する．端末での適用確認までは再制限完了と表示しない．解除適用と失効が競合した場合も，終了済み許可を有効状態に戻さない．
4. 実利用時間を確認して残りを破棄時間として記録する．残高の返還・追加減算は行わず，同じ操作の再送でも失効を重複処理しない．
5. 作業開始の場合はグループ通知を生成する．一時停止からの再開は新規の作業開始通知を生成しない．

例：未使用残高が20分，確保済みの解除枠が10分でそのうち3分利用した場合，作業再開で残り7分を破棄し，未使用残高20分は保持する．

通信断中は，端末の開始・再開とサーバーでの失効確定が同時になると保証できない．同期遅延と再制限未確認を表示し，復旧時に操作順序を照合する．古い開始イベントで後から発行した別の利用枠を失効させないための順序・関連づけ，オフライン開始の許容条件はPoC後に確定する．作業中の新たな利用許可要求を許可するかどうかも未決とし，今回の残り時間破棄ルールと区別する．

## 14. 実装前に確定する仕様

### 集中度・報酬

- 集中スコアの算出式
- WORK / DISTRACTION / PENDINGの判定基準
- 保留時間の報酬対象可否
- 報酬換算率，端数処理，獲得上限
- 推定アルゴリズムの結果をサーバーが検証する範囲

### 利用時間

- 実利用時間計測の粒度・重複排除・報告方法と，解除適用時点に計測を揃える方法
- 標準アプリの具体的な常時許可一覧とSafariを含む制御可能範囲
- 複数iPhoneへの対応
- 作業開始・再開による破棄以外の取消・失敗時の返還条件
- 解除失敗・権限取消時の処理
- 再制限に失敗した場合の表示と同期方法

### 開始・終了・グループ・通知

- 最小作業時間の初期値・入力範囲・予定時間との設定上の関係
- 新規要件の初期版への採用優先度
- グループの招待手段・発行権限・有効期限・利用回数・管理権限・再参加・最後の参加者の退出
- 通知に含める作業情報，PCへの通知配信方式と受信・表示の重複排除
- 送信済み通知の遅延到着に対する抑制，オフラインでの作業状態共有
- オフライン開始と利用枠失効の順序制御，作業中の新たな利用許可要求の扱い

### データ管理

- 計測データの保存期間
- 削除要求時の集計・取引履歴の扱い
- オフライン同期の許容期間
- 計測精度とAPI応答時間の数値目標
