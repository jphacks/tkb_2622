# ドメインモデル定義

## 1. 目的・設計方針

本書では，Macでの作業計測から，集中度の評価，報酬時間の確定，iPhoneでの報酬利用・アプリ再制限までを実現するドメインモデルを定義する．

本書は初期版の設計案であり，未決定事項は設計上の暫定値として明示する．

### 基本原則

1. 作業の計測結果と，サーバーで確定した作業結果を区別する．
2. 報酬の確定・残高・利用履歴はバックエンドを正本とする．
3. 報酬操作は冪等に実行し，同時操作でも残高を保護する．
4. iPhoneのアプリ制限操作は端末の責務とし，サーバーでは利用許可を管理する．
5. 作業・脱線・保留を区別し，判定根拠と推定方法のバージョンを保持する．
6. 同期失敗・解除失敗・権限拒否を正常完了と区別する．

## 2. 境界づけられたコンテキスト

| コンテキスト                   | 責務                                                 |
| ------------------------------ | ---------------------------------------------------- |
| Identity                       | ユーザー識別，端末登録，データアクセス権限           |
| Focus                          | タスク設定，作業計測，行動分類，集中度評価，結果確定 |
| Reward                         | 報酬換算，報酬付与，残高管理，取引履歴               |
| Restriction                    | 制限設定，利用許可，解除期限，再制限の状態管理       |
| Synchronization / Notification | 再送管理，同期，通知イベントの処理                   |

各コンテキストは論理的に分割し，初期版では単一のGoアプリケーション内に実装する．

## 3. Identityコンテキスト

### 3.1 User（ユーザー）

**種別：集約ルート**

同一アカウントをMacとiPhoneで利用するための識別単位．

| 属性        | 型         | 説明                 |
| ----------- | ---------- | -------------------- |
| id          | UserID     | ユーザー識別子       |
| authSubject | String     | 外部認証基盤の識別子 |
| createdAt   | DateTime   | 登録日時             |
| status      | UserStatus | ACTIVE / DISABLED    |

**不変条件**

- `UserID`は変更されない．
- 外部認証基盤の識別子は，認証プロバイダーを含めて一意に対応づける．
- ユーザーの作業記録・報酬を操作する際は，認証済み主体との対応を検証する．

### 3.2 Device（端末）

**種別：エンティティ**

| 属性         | 型           | 説明             |
| ------------ | ------------ | ---------------- |
| id           | DeviceID     | 端末識別子       |
| userId       | UserID       | 所有ユーザー     |
| platform     | Platform     | MACOS / IOS      |
| deviceName   | String       | 表示用端末名     |
| lastSyncedAt | DateTime?    | 最終同期日時     |
| status       | DeviceStatus | ACTIVE / REVOKED |

APNsのデバイストークンは通知インフラ層で管理し，端末との関連を保持する．認証トークンや秘密情報をドメインエンティティへ直接含めない．

## 4. Focusコンテキスト

### 4.1 Task（タスク）

**種別：集約ルート**

ユーザーが行う作業の設定を表す．

| 属性            | 型           | 説明         |
| --------------- | ------------ | ------------ |
| id              | TaskID       | タスク識別子 |
| userId          | UserID       | 所有ユーザー |
| name            | String       | 作業名       |
| category        | TaskCategory | 作業種類     |
| plannedDuration | Duration     | 予定作業時間 |
| createdAt       | DateTime     | 作成日時     |

**TaskCategoryの例**

- PROGRAMMING
- DOCUMENT_WRITING
- READING
- DESIGN
- STUDY
- OTHER

タスク設定は再利用可能とする．過去の作業結果が変更されないように，セッション開始時にはタスクの設定内容をスナップショットとして保存する．

### 4.2 WorkSession（作業セッション）

**種別：集約ルート**

作業の開始から終了・結果確定までを表す中心的なモデル．

| 属性           | 型                 | 説明                     |
| -------------- | ------------------ | ------------------------ |
| id             | SessionID          | セッション識別子         |
| userId         | UserID             | 所有ユーザー             |
| deviceId       | DeviceID           | 計測端末                 |
| taskSnapshot   | TaskSnapshot       | 開始時点のタスク情報     |
| status         | SessionStatus      | セッション状態           |
| startedAt      | DateTime           | 開始日時                 |
| endedAt        | DateTime?          | 終了日時                 |
| activeDuration | Duration           | 一時停止を除いた計測時間 |
| evaluation     | SessionEvaluation? | 確定した評価結果         |
| version        | Integer            | 更新競合検知用バージョン |

**SessionStatus**

| 状態                | 意味                           |
| ------------------- | ------------------------------ |
| CREATED             | セッション作成済み             |
| RUNNING             | 計測中                         |
| PAUSED              | 一時停止中                     |
| COMPLETED_LOCAL     | Mac側で終了し，送信待ち        |
| FINALIZING          | サーバーで結果確定中           |
| FINALIZED           | サーバーで結果確定済み         |
| FINALIZATION_FAILED | 確定処理に失敗し，再確認が必要 |

`COMPLETED_LOCAL`はMac側の状態であり，サーバー状態と混同しない．オフライン中はローカルで保持し，サーバーが終了結果を受信した後に`FINALIZING`へ移行する．

**操作**

- `start()`
- `pause()`
- `resume()`
- `finish()`
- `finalize(evaluation)`

**不変条件**

- 終了済みセッションを再開できない．
- 一時停止中は作業時間を加算しない．
- 同一セッションの評価結果は一度だけ確定する．
- 確定後の評価結果は通常操作では変更できない．
- 集計時間は計測区間から導出し，単純なクライアント申告値だけで確定しない．

### 4.3 ActivitySegment（行動区間）

**種別：値オブジェクト**

作業セッション内の一定時間区間について，行動判定の結果を表す．

| 属性             | 型                         | 説明                         |
| ---------------- | -------------------------- | ---------------------------- |
| interval         | TimeInterval               | セッション内の計測区間       |
| classification   | ActivityClass              | 行動分類                     |
| confidence       | Float                      | 推定の確信度                 |
| reasons          | List&lt;EvidenceReason&gt; | 判定根拠                     |
| evaluatorVersion | String                     | 判定アルゴリズムのバージョン |

**ActivityClass**

- WORK：作業
- DISTRACTION：脱線
- PENDING：判断保留

判定に十分な根拠がない場合は`PENDING`とする．

例えば，入力操作がないという理由だけで，読書中の時間を脱線と確定しない．

### 4.4 ActivityEvidence（行動判定の根拠）

**種別：値オブジェクト**

| 属性             | 型              | 説明               |
| ---------------- | --------------- | ------------------ |
| kind             | EvidenceKind    | 根拠の種類         |
| value            | Number / String | 集計・分類された値 |
| observedInterval | TimeInterval    | 観測区間           |

**EvidenceKind**

- FOREGROUND_APP
- KEYBOARD_ACTIVITY
- MOUSE_ACTIVITY
- SCROLL_ACTIVITY
- IDLE_DURATION
- APP_CLASSIFICATION
- WEBSITE_CLASSIFICATION（推奨）
- WORK_PROGRESS（発展）
- SCREEN_ANALYSIS（発展）

原則として，キー入力内容や画面画像そのものではなく，分類結果や集計指標を保持する．

### 4.5 AppClassification（アプリ分類設定）

**種別：エンティティ**

| 属性          | 型                  | 説明                           |
| ------------- | ------------------- | ------------------------------ |
| id            | AppClassificationID | 設定識別子                     |
| userId        | UserID              | 所有ユーザー                   |
| appIdentifier | String              | アプリの識別子                 |
| category      | AppCategory         | WORK / ENTERTAINMENT / UNKNOWN |
| updatedAt     | DateTime            | 更新日時                       |

アプリ分類は集中度推定の入力であり，それだけで作業・脱線を最終確定するものではない．

### 4.6 SessionEvaluation（セッション評価結果）

**種別：値オブジェクト**

| 属性                | 型                          | 説明                   |
| ------------------- | --------------------------- | ---------------------- |
| workDuration        | Duration                    | 作業時間               |
| distractionDuration | Duration                    | 脱線時間               |
| pendingDuration     | Duration                    | 保留時間               |
| focusScore          | Float                       | 集中スコア             |
| validWorkDuration   | Duration                    | 報酬計算対象時間       |
| evaluatorVersion    | String                      | 判定ルールのバージョン |
| segments            | List&lt;ActivitySegment&gt; | 区間ごとの結果         |

**不変条件**

- 各時間は0以上とする．
- 作業・脱線・保留の区間は重複しない．
- `workDuration + distractionDuration + pendingDuration = activeDuration`を満たす．
- `focusScore`は0〜1の範囲で管理する．
- `validWorkDuration`は報酬ポリシーで定義した条件に従って計算する．

初期版では保留時間を報酬対象外とする案を暫定採用する．この扱いは，ユーザーへの説明と実機検証を経て確定する．

## 5. Rewardコンテキスト

### 5.1 RewardPolicy（報酬換算ルール）

**種別：ドメインポリシー**

| 属性              | 型             | 説明                               |
| ----------------- | -------------- | ---------------------------------- |
| id                | RewardPolicyID | ルール識別子                       |
| version           | Integer        | ルールバージョン                   |
| conversionRate    | Decimal        | 有効作業時間から報酬時間への換算率 |
| minimumFocusScore | Decimal        | 報酬対象となる最低集中度           |
| maximumReward     | Duration       | 付与上限                           |
| roundingRule      | RoundingRule   | 端数処理                           |
| effectiveFrom     | DateTime       | 適用開始日時                       |

報酬換算はドメインサービス`RewardCalculator`で実行する．

暫定例：

`earnedSeconds = floor(validWorkSeconds × conversionRate)`

実際には集中スコア条件，上限，端数処理を適用する．

### 5.2 RewardWallet（報酬ウォレット）

**種別：集約ルート**

ユーザーが保有する報酬時間を管理する．

| 属性           | 型       | 説明           |
| -------------- | -------- | -------------- |
| userId         | UserID   | 所有ユーザー   |
| balanceSeconds | Integer  | 利用可能な秒数 |
| version        | Integer  | 更新競合検知   |
| updatedAt      | DateTime | 更新日時       |

**操作**

- `credit(reward)`
- `reserve(grant)`
- `release(reservation)`
- `getBalance()`

**不変条件**

- `balanceSeconds >= 0`を常に満たす．
- 同じ報酬付与原因で二重に加算しない．
- 同じ利用要求で二重に差し引かない．
- 残高の更新と取引履歴の登録は同一トランザクションで確定する．

### 5.3 RewardTransaction（報酬取引）

**種別：エンティティ**

| 属性          | 型              | 説明           |
| ------------- | --------------- | -------------- |
| id            | TransactionID   | 取引識別子     |
| userId        | UserID          | 対象ユーザー   |
| type          | TransactionType | 取引種類       |
| amountSeconds | Integer         | 増減する秒数   |
| sourceId      | String          | 発生元の識別子 |
| balanceAfter  | Integer         | 取引後残高     |
| occurredAt    | DateTime        | 確定日時       |

**TransactionType**

- EARN：報酬獲得
- SPEND：報酬利用枠の確保
- REFUND：未利用枠の返還
- ADJUST：管理・補正（将来拡張）

取引履歴は原則として削除・上書きせず，誤処理の訂正は補正取引で表現する．

### 5.4 RewardGrant（報酬付与記録）

**種別：エンティティ**

| 属性          | 型            | 説明               |
| ------------- | ------------- | ------------------ |
| id            | RewardGrantID | 付与識別子         |
| sessionId     | SessionID     | 対象セッション     |
| userId        | UserID        | 対象ユーザー       |
| policyVersion | Integer       | 適用した報酬ルール |
| earnedSeconds | Integer       | 獲得秒数           |
| transactionId | TransactionID | 対応する取引       |
| grantedAt     | DateTime      | 付与日時           |

1つの確定セッションに対する通常の報酬付与は1回に限定する．

## 6. Restrictionコンテキスト

### 6.1 RestrictionPolicy（利用制限設定）

**種別：集約ルート**

iPhoneで制限するアプリと制限方針を管理する．

| 属性      | 型                  | 説明                                     |
| --------- | ------------------- | ---------------------------------------- |
| id        | RestrictionPolicyID | 制限設定識別子                           |
| userId    | UserID              | 所有ユーザー                             |
| deviceId  | DeviceID            | 対象iPhone                               |
| status    | PolicyStatus        | ENABLED / DISABLED / PERMISSION_REQUIRED |
| mode      | UsageTimeMode       | ELAPSED / ACTIVE_USAGE                   |
| updatedAt | DateTime            | 更新日時                                 |

選択したiOSアプリのトークンなど，Appleフレームワーク固有の情報は端末側の安全な領域で管理する．

サーバーには，制限の設定状態や利用許可に必要なメタデータを保持する．

### 6.2 UsageGrant（利用許可）

**種別：集約ルート**

報酬時間を消費して，iPhoneの制限解除を要求した1回の操作を表す．

| 属性             | 型               | 説明                 |
| ---------------- | ---------------- | -------------------- |
| id               | UsageGrantID     | 利用許可識別子       |
| userId           | UserID           | 利用ユーザー         |
| deviceId         | DeviceID         | 対象端末             |
| requestedSeconds | Integer          | 要求された利用秒数   |
| reservedSeconds  | Integer          | 確保された利用秒数   |
| status           | UsageGrantStatus | 利用許可状態         |
| issuedAt         | DateTime         | 発行日時             |
| activatedAt      | DateTime?        | 端末側解除の開始日時 |
| expiresAt        | DateTime?        | 利用許可の終了期限   |
| completedAt      | DateTime?        | 終了確定日時         |

**UsageGrantStatus**

- REQUESTED：利用要求を受信
- RESERVED：残高を確保し，利用許可発行済み
- ACTIVATED：端末が解除を適用したことを確認
- EXPIRED：利用許可の期限終了
- CANCELLED：利用許可の取消確定
- ACTIVATION_FAILED：端末側で解除に失敗

**不変条件**

- 残高不足の利用要求は拒否する．
- 残高の確保と利用許可の発行は同一トランザクションで行う．
- 同一利用要求から複数の利用許可を発行しない．
- 初期版ではユーザーごとに同時に有効な利用許可を1件までとする．
- 利用許可の有効期限後は，サーバーが有効な解除権限として扱わない．
- `ACTIVATED`はサーバーによる許可発行と区別し，端末からの適用確認を必要とする．

解除に失敗した場合でも，残高を即座に返還できるとは限らない．端末側のShield状態を確認し，利用ができなかったことを確認できる場合に返還する．不明な場合は調査・再同期対象とする．

### 6.3 DeviceRestrictionState（端末の制限状態）

**種別：状態スナップショット**

| 属性             | 型               | 説明                 |
| ---------------- | ---------------- | -------------------- |
| deviceId         | DeviceID         | 対象iPhone           |
| permissionStatus | PermissionStatus | 権限状態             |
| shieldStatus     | ShieldStatus     | 制限状態             |
| activeGrantId    | UsageGrantID?    | 適用中の許可         |
| lastAppliedAt    | DateTime?        | 端末での最終適用日時 |
| lastReportedAt   | DateTime         | 最終報告日時         |

**ShieldStatus**

- SHIELDED：制限適用中
- UNSHIELDED：解除中
- UNKNOWN：状態未確認
- ERROR：制御エラー

この情報はiPhoneが報告した状態のスナップショットであり，サーバーから端末の現在状態を常に保証できるものではない．

端末側は，利用許可の期限を確認し，期限終了時に再制限を実行する．サーバーからのPush通知到着だけを再制限の条件にしない．

## 7. Synchronization / Notificationコンテキスト

### 7.1 SyncOperation（同期操作）

**種別：エンティティ**

| 属性            | 型              | 説明                         |
| --------------- | --------------- | ---------------------------- |
| id              | OperationID     | 冪等キー                     |
| userId          | UserID          | 実行ユーザー                 |
| operationType   | OperationType   | 操作種類                     |
| requestHash     | String          | リクエスト内容の識別値       |
| status          | OperationStatus | PENDING / SUCCEEDED / FAILED |
| resultReference | String?         | 確定結果の参照               |
| createdAt       | DateTime        | 作成日時                     |

同一ユーザー・操作種別・冪等キーの再送に対しては，元の処理結果を返す．

同じ冪等キーで異なる内容が送信された場合は，競合として拒否する．

計測データの分割アップロードについても，セッションIDと区間・バッチIDによる重複排除を行う．

### 7.2 NotificationEvent（通知イベント）

**種別：エンティティ**

| 属性        | 型                  | 説明                    |
| ----------- | ------------------- | ----------------------- |
| id          | NotificationEventID | 通知イベント識別子      |
| userId      | UserID              | 通知対象                |
| type        | NotificationType    | 通知種類                |
| referenceId | String              | 元イベント              |
| status      | NotificationStatus  | PENDING / SENT / FAILED |
| createdAt   | DateTime            | 作成日時                |

通知種類の例：

- REWARD_EARNED：報酬獲得
- GRANT_ACTIVATED：利用開始
- GRANT_EXPIRED：利用終了

報酬付与の確定と通知イベントの登録を同一DBトランザクションで行う．APNsへの送信はその後に実行し，失敗時には再試行する．

`SENT`はAPNsが送信要求を受け付けたことを表し，端末への到達・表示を保証しない．

## 8. 主要なドメインサービス

| サービス                         | 責務                                             |
| -------------------------------- | ------------------------------------------------ |
| ActivityEvaluator                | 行動データからWORK / DISTRACTION / PENDINGを判定 |
| FocusScoreCalculator             | 区間データから集中スコアを計算                   |
| RewardCalculator                 | 確定結果とRewardPolicyから報酬秒数を計算         |
| SessionFinalizationService       | セッション評価の確定と報酬付与を調整             |
| RewardWalletService              | 残高の整合性を保ちながら付与・確保・返還         |
| UsageGrantService                | 残高を検証して利用許可を発行・終了               |
| RestrictionReconciliationService | サーバー許可状態とiPhone報告状態の不一致を検出   |

計測値からの分類・集中度計算は，初期版ではMac側で実行してもよい．ただし，サーバーは結果を無条件に信頼せず，区間・合計・識別子・セッション状態を検証する．

## 9. ドメインイベント

| イベント            | 発生契機               | 主な利用先                     |
| ------------------- | ---------------------- | ------------------------------ |
| WorkSessionStarted  | 計測開始               | Focus                          |
| WorkSessionPaused   | 一時停止               | Focus                          |
| WorkSessionFinished | 作業終了               | Focus                          |
| SessionFinalized    | 結果確定               | Reward                         |
| RewardGranted       | 報酬付与               | Notification / Synchronization |
| UsageGrantReserved  | 利用枠確保             | Restriction                    |
| UsageGrantActivated | 端末で解除を適用       | Restriction                    |
| UsageGrantExpired   | 利用許可期限終了       | Restriction                    |
| RestrictionApplied  | 端末でShield適用を報告 | Synchronization                |

これらはドメイン上のイベント定義であり，初期版でKafkaなどのメッセージブローカーを導入することを意味しない．

## 10. 主要な処理と整合性

### 10.1 集中セッションの確定と報酬付与

1. Mac側で作業区間を計測する．
2. Mac側で行動分類・集中スコアを推定する．
3. 終了結果を同一SessionID・冪等キーでサーバーへ送信する．
4. サーバーでセッション状態，計測区間，集計値を検証する．
5. `SessionEvaluation`を確定する．
6. `RewardPolicy`に従って報酬を算出する．
7. 1つのDBトランザクションで`RewardGrant`，`RewardTransaction`，`RewardWallet`，通知Outboxを更新する．
8. 確定結果をMacへ返す．

同時再送の場合も，同一SessionIDに対する付与の一意制約で二重付与を防止する．

### 10.2 報酬の利用

初期版では，利用時間を「解除開始後の経過時間」で消費する方式を暫定採用する．

1. iPhoneで利用したい秒数を選択する．
2. `UsageGrantService`に利用許可を要求する．
3. サーバーが残高と同時利用状態を検証する．
4. 1つのDBトランザクションで残高を確保し，取引履歴と利用許可を記録する．
5. iPhoneで解除許可を受信し，Shieldを解除する．
6. iPhoneが適用結果をサーバーへ報告する．
7. 端末側で解除期限を管理し，期限終了後に再制限する．
8. 次回同期で端末の制限状態と利用許可を照合する．

初期版では，確保した時間を原則として1回の解除枠に充当する．途中終了や解除失敗時の返還は，実利用の確認方法を定めたうえで実装する．

### 10.3 通信障害

- Macの未送信記録は端末内に保存する．
- 同一セッションの送信は同一識別子で再試行する．
- API応答が失われた場合は，新しい報酬を付与するのではなく既存結果を照会する．
- iPhoneが解除許可を受信できなかった場合も，操作IDで確定状態を照会する．
- iPhoneの解除状態が不明な場合，成功・失敗を推測して残高を修正しない．
- APNs通知の失敗は報酬確定の取消理由としない．

## 13. 実装前に確定する仕様

- 報酬換算率，端数処理，獲得上限

- 解除失敗・権限取消時の処理

- オフライン同期の許容期間
