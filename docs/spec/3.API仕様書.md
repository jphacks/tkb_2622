# API仕様書

## 位置づけ

[機能・非機能要件](../strategy/2.機能-非機能要件.md)と[ドメインモデル定義](4.ドメインモデル定義.md)に対応する，API操作と責務の整理．ヘルスチェックとUserテーブルは実装済み．それ以外の業務RPC名，Protocol Buffersのメッセージ・フィールド，エラーコード，DBスキーマは未定であり，後述の業務操作は設計案である．通信は採用済みのConnect RPC / HTTPSを用いる．

## 現在実装しているヘルスチェック

`backend/`の最小実装では，以下だけを公開する．後述の業務操作・認証は未実装．

| 方式 | パス | 応答 |
| --- | --- | --- |
| HTTP | `GET /healthz` | 200，`{"status":"ok"}` |
| Connect互換標準Health | `POST /grpc.health.v1.Health/Check` | `{"service":""}`に対して`{"status":"SERVING_STATUS_SERVING"}` |

公式`connectrpc.com/grpchealth`の標準ハンドラーを使用し，独自protoは定義しない．いずれもAPIプロセスの生存確認であり，DB接続やマイグレーション完了の確認は行わない．ローカル起動ではComposeがマイグレーション成功後にAPIを起動する．手順は[backend README](../../backend/README.md)を参照する．

## 必要な操作と責務

| 操作 | 要求・結果として扱う情報 | サーバーの責務 |
| --- | --- | --- |
| タスク設定 | 作業内容，予定時間，最小作業時間 | 本人の設定を管理し，セッション開始時にスナップショットを保持する |
| 作業開始・一時停止・再開 | セッション・端末・操作の識別，作業状態 | 状態遷移を検証する．開始・再開時は未終了の利用枠を失効させ，状態と原子的に確定する |
| 通常終了・結果確定 | 本人の終了操作，計測区間・集計結果 | 一時停止を除く計測時間が開始時点の最小時間以上であることを検証し，報酬を一度だけ確定する |
| 作業中止 | セッションと中止操作 | 履歴を保存し，報酬は付与しない．通常終了との競合を拒否する |
| 制限設定の同期 | アプリ指定／全体のモード，実利用時間方式，設定・認可の状態 | 利用許可に必要なメタデータを扱う．Apple固有のアプリトークンは端末に保持する |
| 利用枠の確保 | 対象端末，要求秒数，操作識別 | 残高を確保し，利用許可を発行する．同時発行と作業開始・再開の順序を制御する |
| 実利用・制限適用の報告 | 利用許可，実利用時間，端末の制限状態 | 消費完了・失効・端末での再制限を照合する．失効済みの許可を遅延報告で復活させない |
| 状態照会・再同期 | セッション，操作結果，残高，利用許可，制限状態 | 同期遅延・精算未確認・適用未確認を成功と区別して返す |
| グループ作成・招待・受諾・退出 | グループ・招待・利用者の識別 | 招待と所属を管理し，認可と重複受諾を検証する．管理権限の詳細は未定 |
| グループ・所属の参照 | 本人が参加するグループと参加状態 | 非参加者への情報公開を防ぐ．他人の報酬や作業履歴を操作する権限は与えない |
| 通知配信 | 元イベント，通知対象端末，通知種別 | 作業状態に応じて報酬通知を抑制し，グループ開始通知は現在の参加者へ送る．PCの配信方式は未定 |

## 共通の整合性

- 本人の操作は認証済み主体と対応づける．グループ操作は所属・招待・権限を検証する．
- 再送可能な変更操作は操作IDで重複排除し，同じIDで異なる内容は拒否する．通常終了・中止・利用枠失効は状態とバージョンも検証する．
- 利用枠は確保時に残高から差し引く．作業開始・再開時の残り破棄では，返還も追加減算もせず未使用残高を保持する．
- サーバーの利用許可失効と，iPhoneでの再制限完了は異なる結果として扱う．通知受信だけで適用成功としない．
- 作業中・一時停止中の報酬通知は送信前にも抑制判定し，抑制後は再送しない．グループ開始通知は作業中も配信する．

## 未決事項

最小時間の入力制約，招待手段・管理権限・共有情報，PC通知配信方式，実利用時間の報告粒度，オフラインでの開始・再開と利用枠の関連づけ・順序制御，作業中の新規利用許可要求，解除失敗時の返還条件は実装前に確定する．API型とエラー表現は，これらの決定とPoC結果を踏まえて定義する．
