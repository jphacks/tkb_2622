# バックエンドの技術スタック

Connect RPC + GO + Tursoで考える.

1. おすすめの技術スタック
   用途 推奨技術 理由
   APIフレームワーク Connect RPC + net/http 軽量でGo標準HTTPと統合できる
   HTTPルーター chi（必要な場合） ルーティング・Middleware管理
   APIスキーマ Protocol Buffers APIの型を明確に定義できる
   コード生成 Buf Protocol BuffersからAPI用コードを生成（Goサーバー・デスクトップのGoクライアント・iOSクライアントの生成設定は別途定義）
   DB Turso 低コストなSQLite互換DB
   DBアクセス sqlc SQLから型安全なGoコードを生成
   マイグレーション goose SQLベース，CLI・Goライブラリに対応
   ログ log/slog Go標準の構造化ログ
   デプロイ Cloud Run スケールアウト・スケールゼロ

## デスクトップアプリとの境界

デスクトップアプリはWails v2を使用し，端末内GoからConnect RPCで本APIへ接続する．WailsによるWeb UI向けバインディング生成と，BufによるクラウドAPI用コード生成は別の役割とする．端末内Goは計測・画面連携・API呼び出しを担い，Cloud Run上のGoは報酬の最終確定・残高管理を担う．
