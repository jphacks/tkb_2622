# Issue の完了条件を満たす

1. Issue の URL が指定されていれば対象を確認する。番号だけなら `gh repo view --json nameWithOwner --jq .nameWithOwner` で現在のリポジトリを取得し、`gh issue view <番号> --repo <対象>` で内容を読む。取得できなければ remote を確認し、解決できない場合は Issue 本文または対象情報を求める。別リポジトリの Issue なら実装対象との関係を確認する。
2. `INDEX.md`、Issue の参照資料、対象の README・実装を確認する。必要なら `docs-navigator` を使う。仕様が未記載でも推測で確定せず、完了条件に影響する未決事項や矛盾を確認する。
3. `git status` と現在のブランチを確認し、利用者の未コミット・未追跡ファイルを保護する。ブランチ操作は依頼と作業状況に合わせる。機械的な main への切り替え、pull、変更の破棄は行わない。
4. 実在する設定・依存関係・開発手順に合わせて実装する。技術スタックや存在しない補助 Skills を前提にしない。ランタイム挙動の変更には受け入れ条件や不具合再現を検証するテストを検討し、文書・設定のみの変更はリンクや設定形式など変更に適した確認を行う。
5. 設定や README に定義されたテスト・lint・build のうち変更に必要なものを実行する。基盤がなければ適切な実行確認・静的確認を行い、未導入・未実行・検証不能を明示する。コマンドを推測して成功扱いにしない。
6. 完了条件を確認し、仕様を変更した場合は関連資料を、資料の追加・移動があれば INDEX を更新する。無関係な改善や外部への Issue 作成は追加しない。
7. 変更内容、完了条件の充足状況、実施した検証と結果、残る未決事項を報告する。

コミット・push・PR 作成・Issue 更新やクローズは必須操作にしない。利用者の依頼に含まれる場合は、その範囲で実施する。
